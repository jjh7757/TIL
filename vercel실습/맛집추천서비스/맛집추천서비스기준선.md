# 맛집 추천 서비스 기준선

[기준선 작성](기준선작성.md)에서 다룬 12개 항목 템플릿을 그대로 적용해,
"예산 기반 맛집 추천" 부트캠프 미니프로젝트의 기준선을 v0.1부터 채워나간다.
수업 예시([오늘 뭐 먹지?](기준선작성.md))는 배달 메뉴 추천+주문이었다면,
이 프로젝트는 배달이 아니라 실제 방문 식당(맛집)을 추천하는 점이 다르다.

### 8시간 목표

로그인해서 예산과 함께 내 맛집을 등록하고, 예산·카테고리로 걸러 보고,
다녀온 곳을 체크하며 별점과 메모를 남길 수 있다.

### 1. 프로젝트 목적

내가 등록해 둔 식당 중에서, 예산과 카테고리 조건에 맞는 후보를 빠르게 걸러
"오늘은 뭘 먹을지" 결정하는 시간을 줄여줍니다. (실시간 지도 검색이 아니라, 직접 등록한
목록 안에서 필터링하는 방식입니다.)

### 2. 문제 정의
- 사용자: 가고 싶은 곳·다녀온 곳을 기록해두고, 그중 예산에 맞는 곳을 고르고 싶은 사람
- 사용 상황: 여러 식당을 기록해뒀지만 예산·카테고리 조건으로 다시 걸러보기 번거로운 상황
- 문제: 목록이 쌓일수록 그때그때 예산에 맞는 곳을 눈으로 찾기 어렵습니다.
- 기대 변화: 예산과 카테고리만 고르면 조건에 맞는 후보를 바로 확인할 수 있도록 합니다.

### 3. 프로젝트 범위 초안

#### 이번 프로젝트에서 다룰 내용
- 식당 직접 등록 (이름·카테고리·주소·예산)
- 예산·카테고리 조건 필터링
- 가고 싶은 곳 / 다녀온 곳 구분, 별점·메모 기록
- 등록한 식당 수정·삭제

#### 이번 프로젝트에서 다루지 않을 것
- 카카오/네이버 지도 API 연동 (실시간 위치 기반 검색)
- 위도·경도 기반 "내 근처" 거리순 정렬
- 실제 예약·웨이팅 연동
- 주문·결제
- 배달
- 다른 사용자가 등록한 식당을 공유해서 보는 기능 (본인이 등록한 목록만 조회)
- 별점·메모를 다른 사용자에게 공개하는 리뷰 기능 (본인만 보는 개인 기록)
- 추천 요청 이력을 별도로 남기는 기능 (조회 시점에 필터링만 함)
- 가격대 자동 추정·다수결 로직
- 별도 즐겨찾기 테이블 (등록된 행 자체가 이미 내 목록)

### 4. 확인한 사실
- `restaurants` 테이블 하나로 목록·상세·등록 화면 3개를 모두 구현할 수 있습니다 ([DB 설계](맛집추천서비스DB설계.md), [화면 설계](맛집추천서비스화면설계.md) 참고).
- 예산 조건 필터링은 지도 API 없이도 `budget` 컬럼 비교만으로 동작합니다.

### 5. 아직 확인하지 않은 가정
- 사용자가 식당을 직접 등록하는 수고를 들여도, 이후 필터링 편의가 그 수고를 상쇄할 것입니다.
- 예산·카테고리 조건만으로도 "오늘 뭐 먹지" 결정에 충분한 후보를 얻을 것입니다.
- 등록 건수가 적은 초기 상태에서도 서비스가 유용하게 느껴질 것입니다. (등록 전 빈 목록 경험이 어색하지 않을지 확인 필요)
