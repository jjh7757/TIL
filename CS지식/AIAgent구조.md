# AI Agent란 — 서비스 구조와 실행 환경

수업 중 손글씨 판서를 정리한 내용입니다.

## 전체 흐름

```
Client(가상) ──▶ ① AI(LLM) Agent ──▶ ② Server(Rest API) ──▶ ③ DB
                                                              │
                                                    ④ Cloud(AWS / GCP / NHN)
```

1. **Client**: 요청을 보내는 주체 (가상의 클라이언트로 표현)
2. **AI(LLM) Agent**: 요청을 받아 LLM 기반으로 판단·처리하는 계층
3. **Server(Rest API)**: Agent와 외부(Client, DB)를 연결하는 REST API 서버
4. **DB**: Agent/서버가 사용하는 데이터 저장소
5. **Cloud**: 위 구성 요소들이 실제로 돌아가는 인프라 (AWS, GCP, NHN 등)

## 로컬 AI 실행 환경 구성 요소

"AI 실행 환경"을 로컬에서 갖추려면 아래 세 가지가 필요합니다.

- **.py** — 실행할 파이썬 코드 파일
- **Code** — Agent/서비스 로직 코드
- **DBMS** — 데이터를 저장·관리할 DB 관리 시스템

## 왜 로컬 컴퓨터가 아니라 클라우드인가

- 개인 컴퓨터는 **24시간 365일** 켜둔 채로 서비스를 운영하기 어렵다 (전기, 안정성, 네트워크 등 문제).
- 그래서 실제 서비스는 컴퓨터를 직접 돌리는 대신 **클라우드 서버를 빌려서 실행**한다.
- 대표적인 클라우드 제공자: **AWS**, **GCP**, **NHN Cloud** 등.

## 정리

AI Agent 서비스는 단순히 LLM 하나로 끝나는 게 아니라, Client ↔ Agent ↔ Server(REST API) ↔ DB로 이어지는 구조를 가지고 있고, 이 전체가 24/365 안정적으로 돌아가려면 로컬 컴퓨터 대신 클라우드 인프라 위에 올려야 합니다.
