# 스코프(Scope)

스코프는 **변수가 살아있는(접근 가능한) 범위**다. 어떤 변수를 어디서 참조할 수 있는지는 그 변수가 "어디서 만들어졌는가"로 정해진다.

## 함수 내부 변수는 외부에서 접근 불가능

```python
def func():
    value = 10
    print(value)   # 함수 내부에서는 접근 가능

func()
print(value)   # NameError — 함수 밖에서는 접근 불가능
```

함수 내부에서 만든 변수는 그 함수 안에서만 존재한다. 함수 호출이 끝나면 사라지므로, 외부에서는 애초에 정의된 적 없는 이름이 된다.

## LEGB 규칙

파이썬이 변수 이름을 찾는 순서는 4단계다.

| 순서 | 이름 | 의미 |
|---|---|---|
| L | Local | 현재 함수 내부 |
| E | Enclosed | 자신을 감싸고 있는 바깥 함수 |
| G | Global | 모듈(파일) 최상단 |
| B | Built-in | 파이썬이 기본 제공하는 이름(`len`, `print` 등) |

안쪽 스코프부터 바깥쪽으로 차례로 찾아 나가다가, 가장 먼저 찾은 이름을 사용한다.

## 함수 외부 변수는 내부에서 읽을 수 있다

```python
value = 30

def func():
    print(value)   # global의 value를 읽음(LEGB에 따라 G 단계에서 발견)

func()
```

## Enclosed — 중첩 함수의 바깥 변수

```python
def outer():
    value = 40   # outer 입장에서는 local, inner 입장에서는 enclosed

    def inner():
        print(value)   # inner의 local에는 없으니 한 단계 바깥(enclosed)에서 찾음

    inner()

outer()
```

## 함수 내부에서 외부 값을 바꿔도 외부에는 영향이 없다

```python
value = 50

def func():
    value = 500000   # 같은 이름의 새 local 변수를 만드는 것 — global과 무관
    print(value)      # 500000

func()
print(value)   # 50, 그대로
```

함수 안에서 `value = ...`처럼 **대입**하는 순간, 파이썬은 그 이름을 global이 아니라 해당 함수의 local 변수로 취급한다. 그래서 이름이 같아도 서로 다른 변수다.

## `global` 키워드 — 예외적으로 외부에 영향을 줄 수 있는 경우

```python
value_6 = 60
value_7 = 70

def func():
    global value_6   # 이 함수 안에서 value_6은 local이 아니라 global의 것을 가리키게 선언

    value_6 = 6000000
    value_7 = 7000000   # global 선언이 없으니 그냥 local 변수

func()
print(value_6)   # 6000000 — 바뀜
print(value_7)   # 70 — 그대로
```

`global`로 선언한 이름은 함수 안에서 대입해도 새 local을 만들지 않고 바깥의 global 변수를 직접 수정한다.

> `global`은 알고리즘 문제를 풀 때는 편의상 쓰기도 하지만, 실제 개발에서는 **사용하지 않는 것**이 좋다. 어디서 값이 바뀌는지 추적하기 어려워지고 함수의 예측 가능성(함수는 입력에만 의존해야 한다는 원칙)이 깨지기 때문이다.

## 참고: 파이썬은 block scope가 없다

C, Java 등과 달리 파이썬은 `if`, `for` 등의 블록이 별도의 스코프를 만들지 않는다.

```python
if True:
    value_8 = 30

print(value_8)   # 30 — 블록 밖에서도 접근 가능
```

`if`/`for` 블록 안에서 만든 변수는 (함수가 아니므로) 그대로 같은 스코프에 남는다. 다른 언어 경험이 있다면 헷갈리기 쉬운 부분이다.
