# 파이썬 추가 문법 모음

지금까지 다룬 문법을 보충하는 짧은 주제들을 모은 문서다.

## `*args`, `**kwargs` — 개수를 모르는 인자 받기

- `*args`: 여러 개의 위치 인자를 튜플로 묶어 받는다.
- `**kwargs`: 여러 개의 키워드 인자를 딕셔너리로 묶어 받는다.

```python
def show_info(*args, **kwargs):
    print(args, type(args))     # (10, 20) <class 'tuple'>
    print(kwargs, type(kwargs)) # {'name': '철수', 'age': 25} <class 'dict'>

show_info(10, 20, name="철수", age=25)
```

## 패킹과 언패킹

패킹은 여러 값을 하나로 묶는 것이고, 언패킹은 묶인 값을 다시 펼치는 것이다. 함수를 호출할 때 `*`는 리스트·튜플을, `**`는 딕셔너리를 풀어서 각각의 인자로 전달한다.

```python
numbers = (10, 20, 30)   # 패킹
a, b, c = numbers        # 언패킹

def add(x, y):
    return x + y

values = [10, 20]
print(add(*values))      # add(10, 20)과 동일

def introduce(name, age):
    print(name, age)

user = {"name": "영희", "age": 20}
introduce(**user)        # introduce(name="영희", age=20)과 동일

print(*[1, 2, 3, 4])     # print(1, 2, 3, 4)와 동일 — 리스트를 낱개 인자로 풀어서 전달
```

## 얕은 복사와 깊은 복사

`b = a`는 복사가 아니라, 두 변수가 같은 리스트를 가리키는 대입일 뿐이다. 진짜로 복사하려면 다음 둘 중 하나를 선택해야 한다.

- **얕은 복사**: 바깥 리스트만 새로 만들고, 안에 든 리스트(내부 객체)는 원본과 공유한다.
- **깊은 복사**: 안에 든 리스트까지 전부 새로 만든다.

```python
import copy

original = [[1, 2], [3, 4]]
shallow = original.copy()        # 또는 original[:]
deep = copy.deepcopy(original)

original[0].append(100)

print(original)  # [[1, 2, 100], [3, 4]]
print(shallow)   # [[1, 2, 100], [3, 4]]  — 내부 리스트를 공유해서 같이 바뀜
print(deep)      # [[1, 2], [3, 4]]        — 완전히 독립적
```

## `with` — 자원을 안전하게 정리하기

`with`로 파일을 열면 블록이 끝날 때(오류가 나도) 자동으로 파일을 닫아준다. [예외 처리](14_예외처리.md)의 `finally`가 하던 "무조건 정리" 역할을 문법 차원에서 대신해준다.

```python
with open("example.txt", "w", encoding="utf-8") as file:
    file.write("안녕하세요")

with open("example.txt", "r", encoding="utf-8") as file:
    content = file.read()
```

## `__str__` vs `__repr__`

둘 다 [매직 메서드](15_클래스.md#매직-메서드--내장-함수연산자와-연결하기)로, 객체를 문자열로 바꿀 때 쓰인다. `__str__`은 **사용자**가 보기 편한 표현(`print()`가 우선 사용), `__repr__`은 **개발자**가 객체를 식별하기 위한 표현이다(리스트 안에 담겨 출력될 때 등).

```python
class Product:
    def __init__(self, name, price):
        self.name = name
        self.price = price

    def __str__(self):
        return f"{self.name} - {self.price}원"

    def __repr__(self):
        return f"Product({self.name!r}, {self.price})"

product = Product("키보드", 50000)
print(str(product))    # 키보드 - 50000원
print(repr(product))   # Product('키보드', 50000)
print([product])       # [Product('키보드', 50000)] — 컨테이너 안에서는 __repr__이 쓰인다
```

## `is` vs `==`

- `==`: 두 객체의 **값**이 같은지 비교한다.
- `is`: 두 변수가 **같은 객체**를 가리키는지(메모리 주소가 같은지) 비교한다.

```python
a = [1, 2, 3]
b = [1, 2, 3]
c = a

print(a == b)   # True  — 값이 같다
print(a is b)   # False — 서로 다른 객체다
print(a is c)   # True  — 같은 객체를 가리킨다

value = None
print(value is None)   # None 비교는 관례적으로 is를 쓴다
```

숫자나 문자열 같은 값 비교에는 `==`를 쓴다. `is`는 `None`처럼 이 세상에 단 하나만 존재한다고 보장되는 값을 비교할 때 쓴다.

## 제네릭 — 하나의 함수를 여러 타입에 쓰기

[타입 힌트](19_타입힌트와독스트링.md)는 자료형을 보여주지만 실행 중에 강제하지는 않는다. 제네릭은 "입력이 무슨 타입이든, 반환값도 같은 타입"이라는 관계를 표현할 수 있게 해준다.

```python
from typing import TypeVar

T = TypeVar("T")

def get_first(items: list[T]) -> T:
    return items[0]

print(get_first([1, 2, 3]))          # int가 들어가면 int가 나온다
print(get_first(["가", "나", "다"]))  # str이 들어가면 str이 나온다
```

## 덕 타이핑과 `Protocol`

[추상 클래스와 다형성](17_추상클래스와다형성.md)에서 ABC로 "반드시 구현해야 함"을 강제하는 법을 봤다. `typing.Protocol`은 상속 없이도 "이런 메서드가 있어야 한다"는 조건을 타입 힌트로 표현해서, 덕 타이핑의 유연함과 정적 타입 검사를 동시에 가져간다.

```python
from typing import Protocol

class Speaker(Protocol):
    def speak(self) -> str: ...

class Dog:
    def speak(self) -> str:
        return "멍멍"

class Cat:
    def speak(self) -> str:
        return "야옹"

def make_sound(animal: Speaker):   # Dog, Cat 모두 Speaker를 상속하지 않았다
    print(animal.speak())

make_sound(Dog())
make_sound(Cat())
```

| | 강제 시점 | 상속 필요 여부 |
|---|---|---|
| ABC | 런타임(인스턴스 생성 시 에러) | 필요 |
| `Protocol` | 정적 분석 도구(타입 체커) | 불필요 — `speak()`만 있으면 통과 |

공통 구현을 재사용하거나 런타임에 규칙을 강제해야 하면 ABC가, 상속 관계보다 "어떤 기능을 제공하는가"가 중요하면 `Protocol`(덕 타이핑)이 적합하다.

## 제너레이터 — 값을 미리 다 만들지 않고 하나씩

일반 함수는 `return`으로 결과를 한 번에 반환하고 끝나지만, 제너레이터는 `yield`로 값을 하나 내보내고 그 자리에서 **실행을 멈춘 채 대기**한다. `next()`를 호출하면 멈췄던 지점부터 다음 `yield`까지 다시 실행된다.

```python
def simple_generator():
    print("첫 번째 값을 생성합니다.")
    yield "A"
    print("두 번째 값을 생성합니다.")
    yield "B"

gen = simple_generator()
print(next(gen))   # 첫 번째 값을 생성합니다. / A
print(next(gen))   # 두 번째 값을 생성합니다. / B

# for문은 내부적으로 next()를 반복 호출한다
for text in simple_generator():
    print(text)
```

모든 값을 리스트로 미리 만들어두는 대신, 필요할 때마다 하나씩 계산하므로 메모리를 적게 쓰고 첫 값을 더 빨리 얻을 수 있다. 데이터가 크거나(파일, 스트리밍), 전체 크기를 알 수 없거나(무한 수열), 한 번만 순서대로 처리한다면 리스트보다 제너레이터가 적합하다. 반대로 데이터가 작고 여러 번 반복 사용해야 한다면 리스트가 더 편하다.
