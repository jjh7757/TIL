# 교차검증과 데이터 누수

소규모 데이터(수백 건)로 회귀 모델을 만들 때, 모델보다 먼저 **검증 틀**을 만들어야 하는 이유와 데이터 누수를 막는 규칙을 정리했습니다.

> 특정 대회·데이터와 무관하게 적용되는 일반 내용만 담았습니다.

## 검증 틀을 먼저 만드는 이유

정답이 없는 평가 데이터(test)로는 내 모델이 잘하는지 알 수 없습니다. 그래서 학습 데이터를 나눠 "학습에 쓰지 않은 부분"으로 점수를 구합니다(교차검증, CV).

데이터가 적을수록 **어떻게 나누느냐에 따라 점수가 크게 흔들립니다.** 실험마다 분할이 다르면 점수 차이가 모델 때문인지 분할 때문인지 구분할 수 없습니다.

| 문제 | 해결 |
|---|---|
| 실험마다 분할이 달라 비교가 안 됨 | 폴드 분할을 **파일로 저장**해 모든 실험이 공유 |
| 분할 한 번의 우연에 점수가 좌우됨 | 시드를 바꿔 **반복 CV**하고 평균·편차를 함께 확인 |
| 폴드마다 타깃 분포가 달라 점수가 불안정 | 타깃을 분위수 구간으로 나눠 **층화(Stratified)** |

### 회귀에서의 층화

`StratifiedKFold`는 분류용이지만, 회귀 타깃을 `pd.qcut`으로 구간화한 값을 층(strata)으로 넘기면 쓸 수 있습니다.
구간을 잘게 나눌수록 폴드 간 평균 차이가 줄어듭니다(무층화일 때보다 크게 감소).

- 극단값이 몇 개 있다면 층화만으로는 한 폴드에 몰릴 수 있어, 극단값을 **별도의 층**으로 분리해 폴드에 고르게 배분했다.
- 각 층의 샘플 수는 폴드 수보다 많아야 한다(층 하나가 `n_splits`보다 작으면 경고).

## OOF 점수

OOF(out-of-fold)는 "각 샘플을 **자기가 속한 폴드를 빼고 학습한 모델**로 예측한 값"입니다. 전체 샘플에 대해 학습에 쓰이지 않은 예측이 하나씩 생기고, 이 예측들로 계산한 RMSE가 CV 점수입니다.

```python
def run_cv(fit_predict, folds):
    for k in folds.unique():
        va = folds == k
        tr = ~va
        pred[va] = fit_predict(tr, va)   # 전처리 fit은 반드시 tr로만
    return rmse(y, pred)
```

- OOF 예측은 저장해 두면 나중에 **앙상블·오차 분석**에 그대로 쓸 수 있다.
- 평균 점수만 보면 "우연히 좋았던 것"과 구분이 안 되므로 폴드별 점수와 시드별 편차를 함께 본다.

## 기준선(baseline)부터 잰다

모델 없이 **평균값만 예측**해도 RMSE는 타깃의 표준편차와 같습니다. 이것이 바닥 점수입니다.

- 모델 점수는 이 기준선과 비교해서 해석한다.
- 검증 틀의 오류를 잡는 데도 쓴다. 틀이 올바르면 평균 예측의 CV 점수가 **타깃 표준편차와 거의 일치**해야 한다.

## 데이터 누수를 막는 규칙

누수가 있으면 CV 점수만 좋아 보이고 실제 성능은 따라오지 못합니다.

| 하지 말아야 할 것 | 올바른 방법 |
|---|---|
| 전체 데이터로 스케일러·PCA를 fit한 뒤 분할 | **폴드의 train 부분으로만 fit**하고 검증 부분에는 transform만 |
| 하이퍼파라미터를 전체 데이터로 고름 | 내부 CV(`RidgeCV`, `GridSearchCV`)를 **fit 안에서** 수행 |
| 평가 데이터로 정규화 통계·순위 변환 계산 | train 통계만 사용, 평가 데이터는 transform/predict에만 사용 |
| 피처가 다른 샘플의 정보를 사용 | 피처를 **샘플 한 건만으로 계산**하면 학습·평가에 동일하게 적용 가능 |

자동 검증 스크립트로 아래를 확인했습니다.
- 폴드를 다시 만들면 저장 파일과 동일한가
- 같은 모델을 두 번 돌리면 같은 점수가 나오는가
- 검증 코드가 평가 데이터 경로를 읽지 않는가

## 리더보드 점수 읽는 법

Public 점수는 평가 데이터의 일부(예: 30%)만으로 계산되므로 **표본이 작아 흔들립니다.**

- 판단 기준은 CV로 두고, Public은 제출 형식과 큰 방향을 확인하는 용도로만 쓴다.
- CV가 개선됐는데 Public이 나빠졌다고 Public을 따라가지 않는다. 반대로 Public만 좋아진 변경은 의심한다.
- 제출 횟수가 제한되므로 CV로 개선이 확인된 변경만 제출한다.

## 눈으로 본 인상은 가설일 뿐

극단 샘플 몇 장을 보고 세운 가설이 전체 데이터에서는 성립하지 않을 수 있습니다. 가설은 **전체 데이터의 상관·분포로 검증**한 뒤에 피처에 반영합니다.
극단 샘플은 선택 효과가 있어 차이가 과장돼 보이므로, 중간 구간 샘플도 함께 비교합니다.

## 삽질 기록

| 문제 | 원인 | 해결 |
|---|---|---|
| `cv2.imread`가 이미지를 못 읽음 | 프로젝트 경로에 **한글 폴더명** | `cv2.imdecode(np.fromfile(path, dtype=np.uint8), ...)` 사용 |
| `import torch` 실패 (WinError 4551) | Windows 애플리케이션 제어 정책이 DLL 차단 | 재확인하니 정상, 재발 시 코랩 사용 |
| 노트북 실행 중 `ImportError` | `skimage.restoration.estimate_sigma`가 `PyWavelets`에 의존 | 설치 후 `requirements.txt` 갱신 |
| 노트북 후반부에서 `ValueError` | 앞 셀에서 쓴 변수명(`sub`)을 루프 안에서 덮어씀 | 변수명 재사용 금지, 필요하면 다시 로드 |
| 그림 저장 중 간헐적 `OSError` | 파일이 다른 프로세스에 잠깐 잠김 | 재실행 |
| 셀을 계속 고치다 상태가 꼬임 | 노트북은 실행 순서와 수정 이력이 남지 않음 | 노트북을 **생성 스크립트로 만들어** 재현 가능하게 함 |

## 정리

1. 모델보다 **검증 틀**(저장된 폴드, OOF, 기준선)을 먼저 만든다.
2. 전처리와 하이퍼파라미터 선택은 **폴드의 train 안에서만** 한다.
3. 판단 기준은 CV, 리더보드는 확인용이다.
4. 눈으로 본 인상은 수치로 검증한다.
5. 재현성(시드 고정, 버전 기록, 생성 스크립트)은 처음부터 챙긴다.
