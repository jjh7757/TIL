# API 기초

API(Application Programming Interface)는 서로 다른 프로그램(또는 프로그램과 사용자)이 **정해진 규칙**으로 데이터를 주고받을 수 있게 해주는 접점입니다.

## 왜 필요한가

- 클라이언트(앱, 웹페이지 등)가 서버 내부 코드를 몰라도, **정해진 요청 형식**만 지키면 원하는 기능을 쓸 수 있게 해준다.
- 서버 입장에서는 내부 구현을 자유롭게 바꿔도, API 규격만 유지하면 클라이언트에 영향이 없다.

## Web API의 기본 구성

Web API는 보통 [HTTP](HTTP기초.md) 위에서 동작하며, 요청 하나는 아래 요소로 이루어집니다.

| 구성 요소 | 설명 | 예시 |
|-----------|------|------|
| **엔드포인트** | 요청을 보낼 [URL](URL구조.md) 경로 | `https://api.example.com/users/42` |
| **메서드** | 수행할 동작 (GET/POST/PUT/DELETE 등) | `GET` |
| **헤더** | 인증 정보, 데이터 형식 등 | `Authorization: Bearer <token>` |
| **바디** | 서버로 보낼 데이터 (주로 JSON) | `{"name": "진준형"}` |
| **응답** | 상태 코드 + 결과 데이터 | `200 OK` + `{"id": 42, ...}` |

## REST API란

REST(REpresentational State Transfer)는 API를 설계하는 대표적인 방식으로, 자원을 URL로 표현하고 HTTP 메서드로 행위를 표현합니다.

| 요청 | 의미 |
|------|------|
| `GET /users` | 사용자 목록 조회 |
| `GET /users/42` | id가 42인 사용자 조회 |
| `POST /users` | 사용자 생성 |
| `PUT /users/42` | id 42 사용자 정보 전체 수정 |
| `DELETE /users/42` | id 42 사용자 삭제 |

## API 키 / 인증

- 많은 API는 아무나 호출하지 못하도록 **API 키**나 **토큰**을 요구한다.
- API 키는 비밀번호처럼 취급해야 한다 — 프론트엔드(브라우저) 코드에 그대로 넣으면 누구나 볼 수 있어 노출된다.
- 안전하게 쓰려면 서버(백엔드)에서 키를 보관하고, 클라이언트는 그 서버를 통해서만 API를 호출하는 구조(프록시)가 필요하다.
