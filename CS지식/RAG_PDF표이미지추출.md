# PDF 문서 처리 — 텍스트·표·이미지 추출

PDF에서 텍스트를 읽을 때 표와 이미지가 어떻게 망가지는지 확인하고, `pdfplumber`로 표를 Markdown으로 정리하고 Gemini로 이미지 내용을 읽은 뒤, **본문·표·이미지를 구분해 보관**하고 **유형에 맞게 청킹**하는 과정을 정리했습니다.
청킹·임베딩의 기본은 [RAG 기초](RAG_기초.md), 검색 이후 단계는 [RAG 검색 고도화](RAG_검색고도화.md)를 참고하세요.

```
PDF 텍스트 추출 → 표·이미지 내용 정리 → 유형별로 구분 → 청킹 → 임베딩 → 벡터 저장소 → 검색
```

> 예제 PDF: 한국소비자원 「태블릿 PC 품질비교시험」 보도자료(15페이지). 패키지: `pdfplumber==0.11.10`, `langchain-community`(`PyPDFLoader`), `langchain-google-genai`.

## 1. 일반 텍스트 추출의 한계

`PyPDFLoader`로 1페이지를 읽으면 본문은 나오지만 제품표는 **글자만 이어 붙어** 나온다.

```python
loader = PyPDFLoader(str(pdf_path))
docs = loader.load()          # 페이지당 Document 1개
print(docs[0].page_content)
```

- 표의 글자는 추출되지만 **열 이름과 값의 대응, 병합 셀 구조**를 알 수 없다. (`구분 브랜드 제품명 ... 고가형 삼성 탭 S10+ ...`처럼 한 줄 흐름)
- 읽는 순서도 뒤섞일 수 있다. (이 PDF는 머리말 성격의 "보도자료" 블록이 맨 끝에 붙음)
- `PyPDFLoader`의 `page` 메타데이터는 0부터 시작하므로 **페이지 번호는 `+1`** 해서 쓴다.

## 2. PDF에 데이터가 저장되는 방식

PDF는 "이 내용을 어디에 어떤 모습으로 그릴지"를 저장한다.

| 구성 요소 | 저장되는 정보 |
|-----------|---------------|
| 글자 | 표시할 문자, 글꼴과 크기, 배치 위치 |
| 선·도형 | 시작점·끝점, 위치와 크기, 색상 등 |
| 이미지 | 이미지 데이터와 페이지에 배치할 위치·크기 |

- 화면에서는 하나의 표로 보여도, 제품명과 가격은 **서로 다른 위치의 글자**이고 테두리는 **별도의 선**일 수 있다. 행·열과 셀의 관계가 함께 저장되지는 않으므로, 표를 뽑으려면 글자 배치와 선의 위치로 구조를 **추정**해야 한다.
- 스캔한 PDF는 페이지 전체가 이미지로 저장되기도 한다. 텍스트 정보가 없으면 OCR이나 비전 모델로 읽어야 한다.

## 3. 표를 Markdown으로 정리

```
표 탐색 → 처리할 표 선택 → 표 확인 → 내용 추출 → Markdown으로 정리
```

### pdfplumber가 표를 인식하는 원리

```
경계선 찾기 → 교차점 찾기 → 셀 구성 → 표로 묶기 → 글자 추출
```

- 가로·세로선과 사각형 테두리로 셀 경계를 추정하고, 선이 만나는 위치로 사각형 셀을 만들어 연결된 셀을 하나의 표로 묶는다. 각 셀 안의 글자를 모아 행·열 순서로 정리한다.
- 선이 없는 표는 글자가 **정렬된 위치**로 행·열을 추정할 수 있다. 이미지로만 된 표는 OCR/비전 모델이 필요하다.

### 표 탐색 — 후보 찾기

영역 좌표(bounding box, `bbox`)는 표나 이미지가 차지하는 사각형 범위 `(왼쪽, 위쪽, 오른쪽, 아래쪽)`이다. 필요한 부분만 잘라내거나 원래 위치를 찾는 데 쓴다.

```python
table_candidates = []
with pdfplumber.open(pdf_path) as pdf:
    for page_no, page in enumerate(pdf.pages, start=1):
        tables = page.find_tables()
        for table_no, table in enumerate(tables, start=1):
            table_candidates.append({
                "page_no": page_no, "table_no": table_no, "bbox": table.bbox,
            })
```

- 이 PDF에서는 **표 후보 21개**가 나왔다. 테두리로 둘러싼 안내 박스도 표 후보로 잡히므로 **내용을 확인하고 처리할 표를 골라야** 한다.
- `page.to_image(resolution=120).debug_tablefinder()`로 감지한 선(빨강)·교차점(원)·표 영역(파랑)을 페이지 위에 시각화해 확인할 수 있다.

### 표 선택과 확인

1페이지의 두 번째 표(하단 제품표)를 골라 `page.crop(bbox).to_image()`로 잘라 눈으로 확인한다.

### 빠진 경계 보완해서 추출

예제 표는 **양쪽 바깥 세로선이 없어서**, 표 영역의 좌우 좌표를 세로선으로 보완해 다시 찾는다.

```python
table_settings = {
    "vertical_strategy": "lines",
    "horizontal_strategy": "lines",
    "explicit_vertical_lines": [table_bbox[0], table_bbox[2]],  # 빠진 좌우 경계 보완
}
region = page.crop(table_bbox)
corrected_rows = region.find_tables(table_settings)[0].extract()
```

- 표 **아래 각주**(`*`로 시작하는 줄)도 `extract_text_lines()`로 따로 가져와 표와 함께 보관한다. 각주 없이는 가격의 기준 시점(`**`)을 알 수 없다.
- 각주까지 포함하도록 영역 좌표(`table_with_footnotes_bbox`)를 아래로 확장한다. (나중에 본문에서 이 영역의 글자를 걷어내는 데 쓴다.)

### 셀 내용 정리

추출 직후 `corrected_rows`에는 병합 셀의 빈칸(`None`)과 셀 안 줄바꿈(`\n`)이 남아 있다.

```python
def normalize_cell(value):
    return " ".join((value or "").split())   # None→"", 줄바꿈·연속 공백→한 칸

for extracted_row in corrected_rows[1:]:
    row = [normalize_cell(v) for v in extracted_row]
    if row[0]:
        current_category = row[0]            # '고가형', '저가형'
    else:
        row[0] = current_category            # 병합 셀 빈칸은 직전 값으로 채움
```

- 각 제품 행을 **독립적으로 읽을 수 있게** 구분 값(고가형/저가형)을 모든 행에 채운다. 청크 하나만 검색돼도 의미가 유지되도록 하는 것이다.

### Markdown 표로 변환

```python
def markdown_row(values):
    escaped = [v.replace("|", r"\|") for v in values]   # 셀 안의 |는 열 구분자와 혼동되므로 이스케이프
    return "| " + " | ".join(escaped) + " |"
```

- 열 이름 → `---` 구분선 → 데이터 행 순서로 구성하고 각주를 덧붙인다. 각주의 `*`는 Markdown 강조·목록으로 해석되지 않도록 `\*`로 이스케이프한다.
- 결과는 `text`(Markdown 문자열)뿐 아니라 **`headers`, `rows`, `footnotes`, `bbox`, `table_id`(`page-1-table-2`)**를 함께 딕셔너리로 보관한다. 뒤에서 행 단위로 나눌 때 구조가 필요하기 때문이다.

## 4. 이미지의 내용 읽기

```
이미지 탐색 → 면적 기준으로 선택 → 이미지 확인 → Gemini로 내용 추출
```

### 이미지 탐색과 선택

- `page.images`로 PDF 안에 이미지로 저장된 객체를 찾는다. **로고·아이콘도 포함**되므로 모두 읽으면 낭비다.
- 페이지 면적 대비 비율(`area_ratio`)을 계산해 **10% 초과**인 것만 선택한다. 이 PDF는 전체 14개 중 5페이지의 이미지 1개(페이지의 65%)만 선택됐다.
- 선택한 영역을 `crop(bbox).to_image(resolution=180)`로 렌더링해 **읽을 내용이 잘리지 않았는지** 미리 확인한 뒤 모델에 보낸다. PNG는 파일로 저장하지 않고 `BytesIO` 버퍼의 바이트를 그대로 쓴다.

### Gemini로 추출

이미지를 Base64로 인코딩해 텍스트 지시문과 함께 한 메시지에 담는다.

```python
message = HumanMessage(content=[
    {"type": "text", "text": extraction_prompt},
    {"type": "image",
     "base64": base64.b64encode(image_bytes).decode("ascii"),
     "mime_type": "image/png"},
])
response = llm.invoke([message])
```

지시문의 핵심은 **요약하지 말고 보존**하는 것이다. (검색에 필요한 내용이 빠지면 안 되므로)

```
- 제목과 본문을 읽기 순서대로 작성하고, 내용을 요약하거나 생략하지 마세요.
- 표는 열 이름과 값의 관계가 드러나는 Markdown 표로 작성하세요.
- 수치, 단위, 제품명과 각주를 보존하고, 각주 번호는 수치와 구분하세요.
- 그림 설명은 [그림 설명]으로 구분하세요.
- 읽을 수 없는 부분은 [확인 불가]로 표시하고 내용을 추측하지 마세요.
- 결과 전체를 코드 블록으로 감싸지 마세요.
```

- 읽을 수 없는 부분을 `[확인 불가]`로 표시하게 해서 **추측(환각)을 막는다.**
- **빈 응답이면 예외를 던져 중단**한다. 빈 문자열로 기존 영역의 내용을 덮어쓰지 않기 위해서다.
- 결과는 `bbox`와 함께 보관(원래 위치에 다시 넣기 위해)하고, 원본 이미지와 나란히 놓고 **숫자가 맞는지 사람이 대조**한다.

## 5. 본문·표·이미지를 구분해서 보관

PDF 전체를 한꺼번에 길이 기준으로 청킹하면 **표 중간이 잘린다.** 열 이름과 데이터 행, 각주가 서로 다른 청크로 나뉘면, 검색된 청크 하나만으로는 표를 이해할 수 없다. 그래서 청킹 **전에** 내용을 유형별로 구분해 둔다.

```
PDF 페이지 → [본문 텍스트] [표] [본문 텍스트] [이미지 해석 결과]
```

### 표·이미지 영역의 기존 글자를 제외하고 자리에 끼워 넣기

`build_page_blocks(page, regions)`가 하는 일:

1. `page.filter()`로 **표·이미지 영역 안에 중심점이 있는 글자를 제외**한다. (같은 내용이 중복되지 않게)
2. 남은 본문 줄을 `extract_text_lines()`로 읽어 좌표가 있는 블록으로 만든다.
3. 표·이미지 결과를 같은 목록에 넣고 **bbox 위쪽 좌표 → 왼쪽 좌표 순으로 정렬**해 원래 읽는 순서를 복원한다.
4. 표·이미지 **사이에 연속해서 나온 본문 줄**만 하나의 블록으로 합친다.

### 메타데이터 부여

모든 블록에 출처 메타데이터를 붙이고, 이후 만들어지는 **모든 청크에 전달**한다.

| 키 | 의미 |
|----|------|
| `file_name`, `page_no` | 원문 출처 |
| `content_type` | `text` / `table` / `image` |
| `block_id` | `page-1-block-1` 형태의 블록 ID |
| `table_id`, `image_id` | 표·이미지 식별자 |
| `extraction_method` | `pypdf` / `pdfplumber` / `pdfplumber+gemini` |

- 선택한 표·이미지가 없는 페이지는 기존 `PyPDFLoader` 본문을 그대로 텍스트 블록 하나로 보관한다.
- 일반 청킹과 비교하려고 페이지 본문 `Document`(`rag_documents`)도 따로 만든다. 블록 목록(`document_blocks`)은 별도로 유지한다.

## 6. 청킹

### 일반 청킹 (기준선)

`RecursiveCharacterTextSplitter(chunk_size=1000, chunk_overlap=100)`를 페이지 본문에 적용 → 15페이지가 **청크 23개**가 됐다.

- 겹침 100자는 **목표값**이고, 실제 겹침은 문단·줄바꿈 경계에 따라 달라진다.
- 1페이지에서는 표+각주(511자)가 1,000자 기준 청크 **하나에 우연히 함께** 들어갔다. 일반 청킹은 표 구조를 판단하지 않으므로, 기준 길이를 줄이거나 표가 길어지면 표가 나뉜다.

### 표가 나뉘는 경우 (300자 기준)

같은 표 Markdown을 300자로 나누면 **3개 청크**(255 / 141 / 112자)로 쪼개진다. 열 이름은 첫 청크에만 남고, 뒤쪽 청크에는 데이터 행이나 각주만 남는다. 청크 하나만 검색되면 제품명·가격·단위의 관계를 읽을 수 없다.

### 표를 통째로 유지

본문·이미지 텍스트만 일반 청킹하고 표는 통째로 한 청크로 둔다.

- 표가 잘리지는 않지만 **청크가 커진다.** 표+각주 511자는 300자 기준을 초과한다.
- 길이도 줄이면서 내용을 보존하려면 **행 구조로 나눠야** 한다.

### 헤더와 각주를 반복하며 행 단위로 나누기

`split_table_rows(headers, rows, footnotes, chunk_size)`의 규칙:

- 표가 기준 길이 안에 들어오면 통째로 유지, 넘으면 **데이터 행 사이에서만** 나눈다. **한 행은 절대 자르지 않는다.** (제품명과 가격이 분리되지 않도록)
- **모든 표 청크에 같은 열 이름과 각주를 붙인다.**
- 길이 계산에는 반복되는 헤더·각주·줄바꿈도 포함한다. 실제 출력과 같은 문자열(`render_table`)로 길이를 잰다.
- 헤더·각주·한 행만으로 기준을 넘으면 **초과를 허용**한다. 현재 청크가 비어 있으면 한 행은 반드시 넣는다.
- 데이터 행이 없어도 헤더+각주를 한 번 반환한다.

### 유형에 맞게 청킹

`split_document_blocks(blocks, chunk_size, chunk_overlap)`:

| 블록 유형 | 청킹 방법 |
|-----------|-----------|
| `text`, `image` | 일반 청킹 (`RecursiveCharacterTextSplitter`) |
| `table` | 행 단위 분할(`split_table_rows`), 같은 표의 청크는 `table_part`로 순서 기록 |

- 제품표(4개 데이터 행)는 300자 기준에서 **표 청크 4개**(296 / 291 / 284 / 294자)가 되고, 각각 열 이름과 각주를 포함한다. 같은 `table_id`(`page-1-table-2`)를 유지한다.
- PDF 전체에 적용하면 일반 청킹(1,000자)의 23개가 아니라 **300자 기준 63개** 청크가 된다. (비교 기준이 달라 개수 자체를 비교하면 안 된다.)
- 5페이지 이미지 해석 결과(1,371자)는 `content_type="image"` 청크 5개로 나뉜다.
- 행·열 구조를 추출한 표는 **1페이지 제품표뿐**이다. 다른 표에도 적용하려면 먼저 그 표의 구조를 추출해야 한다. 선택하지 않은 표와, 이미지 해석 결과 **안의** Markdown 표는 일반 청킹 대상이다.
- 300자는 분할 결과를 살펴보기 위한 값이다. 1,000자로 늘려 짧은 제품표가 한 청크로 유지되는지도 비교해 본다.

## 7. 임베딩과 검색으로 연결

생성한 청크를 임베딩해 벡터 저장소에 넣으면 질문과 관련된 내용을 검색할 수 있다. 각 청크의 **출처 메타데이터**(`page_no`, `content_type`, `table_id` 등)를 유지하면 검색 결과가 원문 몇 페이지의 무엇에서 나왔는지 확인할 수 있다. ([벡터 DB](벡터DB.md)의 메타데이터 필터링과 연결)

## 8. 추가 방법론과 대안 도구

- **Contextual Retrieval**: LLM이 문서 전체와 해당 청크를 참고해 만든 **짧은 문맥 설명을 청크 앞에 붙여** 임베딩·검색에 활용한다.
- **표 요약 기반 검색**: 표의 **요약**을 임베딩해 검색하고, 검색된 요약에 연결된 **원본 표**를 답변 근거로 쓴다.
- PDF 텍스트·이미지 추출은 **PyMuPDF**, 표 추출은 **Camelot** 같은 라이브러리도 쓸 수 있다.
- 이미지 속 글자는 LLM 대신 **Tesseract**, **PaddleOCR** 같은 OCR 도구로도 추출할 수 있다.

## 정리

- 일반 텍스트 추출은 표의 **행·열 관계**를 잃는다. 표는 선·글자 좌표로 구조를 추정하는 도구(`pdfplumber`)로 따로 뽑는다.
- 자동 탐지 결과는 후보일 뿐이다. 표는 시각화·크롭으로 **확인 후 선택**하고, 빠진 경계는 설정으로 **보완**하며, 병합 셀은 값을 **채워** 각 행이 독립적으로 읽히게 한다.
- 이미지는 면적 기준으로 거르고, 모델에는 "요약 금지, 보존, 확인 불가 표시"를 지시하며, 결과는 원본과 **사람이 대조**한다.
- 청킹 **전에** 본문·표·이미지를 구분하고 좌표와 ID를 보관해야, 표를 행 단위로 안전하게 나누고(헤더·각주 반복) 출처를 추적할 수 있다.
- 길이 기준 청킹은 표가 우연히 온전할 수도 있고 쉽게 깨질 수도 있다. 표가 길어지거나 기준이 바뀌어도 **구조적으로 보장**되는 방식이 필요하다.
