# 웹 디자인 기초

화면 설계에 들어가기 전에 알아두면 좋은 개념 세 가지 — 무드보드, 반응형 웹, 모바일 퍼스트 — 를 정리한다.

## 무드보드 (Mood Board)

본격적으로 화면(UI)을 그리기 **전에**, 서비스의 전체적인 분위기·톤을 먼저 정하기 위해 색상·이미지·폰트 등 참고 자료를 한 판에 모아 붙인 것.

- **목적**: "이 서비스가 어떤 느낌이어야 하는가"를 팀원끼리 말로 설명하는 대신 **시각적으로 합의**하기 위함 — 디자인 방향을 정하고 나서 실제 화면 설계·컴포넌트 제작으로 넘어감
- **구성 요소**
  - **컬러 팔레트**: 메인/보조/강조 색상 조합
  - **레퍼런스 이미지**: 분위기가 비슷한 다른 서비스·사진·일러스트
  - **폰트(타이포그래피)**: 제목/본문에 쓸 서체 후보
  - **아이콘·질감(텍스처)**: 톤을 보여주는 그래픽 요소
- **만드는 시점**: 기준선·요구사항 정의 이후, 실제 와이어프레임/화면 설계 이전 단계 — 방향을 먼저 정해야 이후 화면 설계에서 색상·폰트를 계속 다시 정하는 시행착오가 줄어듦
- **도구 예시**: Pinterest, Figma, Milanote 등으로 참고 이미지를 모아 보드 형태로 정리

즉 무드보드는 "무엇을 만들지"가 아니라 "어떤 느낌으로 만들지"를 화면 설계 전에 미리 확정해두는 단계다.

### 무드보드 도구 — Pinterest

**Pinterest**: 이미지를 주제별 보드(Board)에 핀(Pin)으로 모아 정리하는 이미지 공유 플랫폼. 디자인 초기 단계에서 가장 널리 쓰이는 무드보드 도구 중 하나다.

- **핀(Pin)**: 마음에 드는 이미지 하나하나를 저장하는 단위 — 원본 출처 링크가 함께 저장됨
- **보드(Board)**: 핀들을 주제별로 묶어두는 폴더 — 예: "카페 앱 UI", "따뜻한 톤 컬러" 처럼 프로젝트/컨셉 단위로 보드를 만들어 관련 이미지를 모음
- **검색·추천 알고리즘**: 키워드로 검색하면 비슷한 톤·스타일의 이미지를 계속 추천해줘서, 하나의 감각적 방향을 빠르게 넓혀갈 수 있음
- **팀 공유**: 보드를 팀원과 공유하면 각자 마음에 드는 이미지를 같은 보드에 추가하면서 자연스럽게 무드보드가 완성됨

이렇게 Pinterest에서 모은 이미지·컬러·폰트 레퍼런스를 근거로, 실제 서비스에 쓸 컬러 팔레트와 톤을 좁혀나가는 식으로 무드보드 작업이 진행된다.

## 반응형 웹과 모바일 퍼스트

화면 크기가 제각각인 여러 기기(PC, 태블릿, 모바일)에 하나의 웹사이트를 대응시키는 두 가지 접근 방식이다.

### 반응형 웹 (Responsive Web Design)

하나의 HTML/CSS 코드가 화면 크기(뷰포트)를 감지해서 레이아웃을 유동적으로 바꾸는 방식. 기기별로 별도 사이트를 만들지 않아도 된다.

- **미디어 쿼리(Media Query)**: CSS에서 화면 너비 등 조건에 따라 다른 스타일을 적용
  ```css
  .container { width: 100%; }

  @media (min-width: 768px) {
    .container { width: 750px; }
  }
  ```
- **뷰포트(Viewport) 메타 태그**: 모바일 브라우저가 PC용 화면을 축소해서 보여주지 않고, 기기 화면 너비 그대로 렌더링하게 함
  ```html
  <meta name="viewport" content="width=device-width, initial-scale=1">
  ```
- **유동 그리드/이미지**: 요소 크기를 px 대신 `%`, `rem`, `flex`, `grid` 등 상대 단위로 잡아 화면이 늘어나고 줄어들어도 깨지지 않게 함

### 모바일 퍼스트 (Mobile First)

반응형 웹을 **만드는 순서**에 대한 전략. PC 화면을 먼저 설계하고 모바일에 맞춰 줄이는(Desktop First) 대신, **모바일 화면을 기준으로 먼저 설계**한 뒤 화면이 커질수록 요소를 추가하는 방식.

- CSS도 이 순서를 따라 `min-width` 미디어 쿼리로 작성한다 (화면이 **커질 때** 스타일 추가)
  ```css
  /* 기본값 = 모바일 */
  .menu { display: none; }

  @media (min-width: 1024px) {
    .menu { display: flex; } /* PC에서만 노출 */
  }
  ```
- **왜 모바일을 기준으로 잡는가**
  - 실제 웹 트래픽에서 모바일 접속 비중이 PC보다 높은 경우가 많음
  - 구글 검색엔진이 **모바일 화면 기준으로 색인(Mobile-First Indexing)** 하기 때문에 SEO에도 유리
  - 좁은 화면에서 핵심 콘텐츠·기능만 남기고 설계하면, 화면이 커질 때 살을 붙이는 게 반대 방향(PC에서 덜어내기)보다 자연스러움

### 반응형 웹 vs 모바일 퍼스트

| 구분 | 반응형 웹 | 모바일 퍼스트 |
|------|-----------|----------------|
| 성격 | 화면 크기에 **대응하는 기술**(미디어 쿼리 등) | 무엇을 **기준으로 먼저 설계**할지에 대한 **전략** |
| 기준 화면 | 기기 상관없이 동일 코드 | 모바일을 기본값으로 두고 확장 |
| 미디어 쿼리 방향 | `max-width`(PC 기준, 작아지면 축소)도 가능 | `min-width`(모바일 기준, 커지면 확장)를 주로 사용 |

즉 모바일 퍼스트는 반응형 웹을 구현하는 여러 방법 중, "모바일을 기본값으로 놓고 위로 확장한다"는 설계 우선순위에 대한 이야기다.
