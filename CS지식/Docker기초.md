# Docker 기초

Docker가 해결하는 문제와 이미지·컨테이너의 관계, 구성 요소를 정리합니다. 배포 관점의 정리는 [컨테이너 기반 배포 기초](컨테이너배포기초.md)에 있습니다. 실습은 [Compose로 PostgreSQL 실행하기](Docker_Compose_PostgreSQL.md) → [FastAPI 컨테이너 실행하기](Docker_FastAPI컨테이너.md) 순서로 이어집니다.

## Docker란

애플리케이션과 실행에 필요한 파일을 **이미지**로 묶고, 그 이미지로 **컨테이너**를 만들어 실행·관리하는 플랫폼입니다.

Python 앱을 소스 코드만 전달하면 받는 사람이 Python과 라이브러리를 직접 준비해야 합니다. Docker를 쓰면 Python 실행 파일, 라이브러리, 소스 코드를 이미지에 담아 전달할 수 있습니다.

## 왜 필요한가

코드가 같아도 **실행 환경이 다르면** 결과가 달라질 수 있습니다.

| 상황 | 생길 수 있는 문제 |
|------|-------------------|
| 개발자마다 Python 버전이 다름 | 쓸 수 있는 문법·라이브러리가 달라짐 |
| 라이브러리 버전이 다름 | 함수 사용법이나 실행 결과가 달라짐 |
| 한 컴퓨터에서 여러 프로젝트 개발 | 프로젝트마다 요구하는 프로그램·버전이 다름 |
| 다른 컴퓨터에 개발 환경 준비 | 설치 항목이나 설정을 빠뜨림 |

같은 이미지를 공유하면 컴퓨터마다 환경을 맞추는 일이 줄어듭니다. 예를 들어 PostgreSQL을 컨테이너로 실행하면 내 컴퓨터에 서버를 직접 설치하지 않아도 됩니다.

## 이미지와 컨테이너

| 개념 | 설명 |
|------|------|
| **이미지** | 컨테이너를 만들 때 쓰는 실행 파일과 설정의 묶음 |
| **컨테이너** | 프로그램을 **격리된 환경**에서 실행하는 단위 |

FastAPI 앱 이미지에 담을 수 있는 것: Python 실행 파일, 라이브러리, 소스 코드, 시스템 라이브러리, 시작 시 실행할 기본 명령.

컨테이너마다 파일과 라이브러리를 따로 쓰므로, 한 컴퓨터에서 Python 3.11 컨테이너와 3.12 컨테이너를 함께 돌려도 서로 영향을 주지 않습니다.

### Python 가상환경과의 차이

| 구분 | Python 가상환경 | Docker 컨테이너 |
|------|-----------------|-----------------|
| 주요 목적 | 프로젝트별 Python **패키지** 관리 | 애플리케이션 **실행 환경** 구성과 격리 |
| 파일·프로세스·네트워크 | 호스트 환경 그대로 사용 | 격리된 환경 사용 |
| PostgreSQL 같은 별도 프로그램 | 설치·격리하지 않음 | 해당 이미지로 실행 가능 |

둘은 배타적이지 않습니다. 컨테이너 안에서 가상환경을 만들어 패키지를 관리할 수도 있습니다.

### 데이터 저장과 볼륨

| 동작 | 컨테이너 자체 저장 공간의 파일 |
|------|------------------------------|
| 중지 후 다시 시작 | **남아 있음** |
| 컨테이너 삭제 | **사라짐** |

DB 데이터처럼 컨테이너를 새로 만들어도 유지해야 하는 내용은 Docker가 컨테이너와 별도로 관리하는 **볼륨**에 둡니다. 이미지는 프로그램을 준비하고, 볼륨은 실행 중 생긴 데이터를 보존합니다. 같은 볼륨을 새 컨테이너에 연결하면 데이터를 다시 쓸 수 있습니다.

## 구성 요소

```
Docker CLI (터미널 명령) ──┐
                           ├─▶ Docker Engine ──▶ 이미지·컨테이너·네트워크·볼륨
Docker Desktop (관리 화면) ┘
```

| 구성 요소 | 역할 |
|-----------|------|
| Docker Engine | 이미지·컨테이너·네트워크·볼륨을 관리하는 실행 엔진 |
| Docker CLI | `docker` 명령줄 도구. 요청을 Engine에 전달하고 결과를 표시 |
| Docker Desktop | 로컬에서 Engine, CLI, Compose를 함께 쓰게 해 주는 앱과 관리 화면 |
| 이미지 레지스트리 | 이미지를 저장·배포하는 서버. Docker Hub가 대표적 |

- CLI가 설치되어 있어도 **Engine이 실행 중이 아니면** 컨테이너를 실행할 수 없다
- **태그**는 이미지에 붙인 이름표다. 같은 태그가 업데이트된 이미지를 가리킬 수 있으므로, 태그가 같다고 내용이 영구히 같은 것은 아니다

### Dockerfile과 Docker Compose

| 구분 | 정의하는 내용 |
|------|---------------|
| Dockerfile | 이미지에 **어떤 프로그램과 파일을 담을 것인가**. 이 파일로 이미지를 만드는 과정이 **빌드** |
| Compose 파일 (`compose.yaml`) | **어떤 컨테이너를 어떤 설정으로 실행하고 연결할 것인가** (이미지, 환경변수, 네트워크, 저장 공간) |

FastAPI와 PostgreSQL을 함께 쓰면 컨테이너를 따로 두고 Compose로 함께 관리합니다. Compose를 쓴다고 여러 컨테이너가 이미지 하나로 합쳐지지는 않습니다.

## Docker Desktop 설치

Docker Desktop에는 CLI와 Compose가 포함되어 있습니다.

**Windows**: 공식 설치 안내에 따라 CPU 종류에 맞는 파일을 내려받습니다. 설치가 진행되지 않으면 관리자 권한 PowerShell에서 WSL을 설치한 뒤 재설치합니다.

```powershell
wsl --install
```

실행 후 안내가 나오면 다음 명령을 실행합니다.

```powershell
Enable-WindowsOptionalFeature -Online -FeatureName VirtualMachinePlatform
```

**macOS** (Homebrew):

```bash
brew install --cask docker-desktop
```

설치 후 Docker Desktop을 실행하고 Engine 시작이 끝날 때까지 기다립니다.
