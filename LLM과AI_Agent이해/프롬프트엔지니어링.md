# 프롬프트엔지니어링
## 좋은 프롬프트의 4요소 :: 역할 - 맥락 - 작업 - 형식
1. 역할
- 누구로서 답해야 하는지 명시한다
2. 맥락
- 어떤 상황, 배경인지 명시한다
3. 작업
- 무엇을 해야하는지 정학히 명시한다
4. 형식
- 결과물의 형식을 명시한다

## 하네스 엔지니어링
- AI 시스템이 올바르게 동작하도록 환경을 설계하는 기술

| 구성 요소 | 역할 | 예시 |
|-----------|------|------|
| **지시 문서 (Instruction Documents)** | 에이전트에게 프로젝트의 규칙, 개발 방식, 코딩 스타일 등을 전달 | `AGENTS.md`, `CLAUDE.md` |
| **아키텍처 제약 (Architectural Constraints)** | 구조적으로 잘못된 코드나 설계가 생성되지 않도록 제한 | 린터(ESLint, Ruff), 디렉토리 구조 규칙, 타입 검사 |
| **피드백 루프 (Feedback Loop)** | 에이전트의 결과를 자동으로 검증하고 실시간으로 교정 | 테스트 자동화, CI/CD, GitHub Actions |
| **지식 저장소 (Knowledge Repository)** | 팀의 의사결정, 설계 배경, 프로젝트 맥락을 지속적으로 축적 | `docs/` 디렉토리, ADR(Architecture Decision Records), Markdown 문서 |
## 컨텍스트 엔지니어링
- AI 시스템에 적절한 정보를 알맞은 시점에 제공하는 방법

## Zero-shot vs Few-shot
- 예시 없이 지시만으로 시키면 Zero-shot, 정답 예시 몇가지 보여주면서 지시하면 Few-shot

## CoT(Chain of Thought)
- 답이 나온 과정을 보여 준 후 답을 보여주는 방식

## Self-Consistency(자기 일관성)
- 여러 번 풀게하고 나은 답을 채택하는 방식

## ReAct(Reasoning+Acting)
- AI 모델이 모르는 것을 도구로 확인하게 만드는 구조

## Tree-of-Thought
- 여러 가능한 사고 경로를 동시에 탐색하고 비교하면서 최적의 해답을 찾는 추론 기법

## 시스템 프롬프트 vs 사용자 프롬프트
- 시스템 프롬프트는  AI의 역할, 행동 원칙, 제약 조건을 정의하고
- 사용자 프롬프트는 AI에게 수행해 달라고 하는 요청을 담는다
