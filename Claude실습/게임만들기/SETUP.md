# Maze Relay — 배포 & 공유 저장소 설정

플레이어끼리 메시지를 주고받게 하려면 두 가지가 필요합니다.

1. 게임을 **한 URL**로 호스팅 (GitHub Pages)
2. 메시지를 **공유 저장소**에 두기 (Supabase)

코드는 이미 준비돼 있고, `game.js` 상단의 키 두 개만 채우면 공유 모드로 전환됩니다.
키를 비워두면 각자 브라우저에만 저장되는 로컬 모드로 동작합니다 (게임은 정상 진행됨).

> ⚠️ **기존 Maze Relay(부트캠프 화이팅 버전)에서 넘어오는 경우**
> 스키마가 바뀌었습니다. 아래 **0단계**를 먼저 실행하세요.

---

## 0단계 — 기존 데이터 정리 (신규 프로젝트면 건너뛰기)

이전 버전의 `messages`에는 격려 문구가, `message_boosts`에는 "힘이 나요" 기록이 들어
있습니다. 새 게임에서 이 문장들은 **목숨을 구걸하는 대사**로 노출되기 때문에 톤이 정반대입니다.
지우고 시작하세요.

```sql
truncate table public.message_boosts;
truncate table public.messages;
```

---

## 1단계 — 테이블 만들기 / 마이그레이션

Supabase 대시보드 → **SQL Editor** 에서 실행합니다.
(계정 생성과 프로젝트 생성은 https://supabase.com 에서 직접 하셔야 합니다. 무료 플랜으로 충분합니다.)

```sql
-- ── messages: 갇힌 사람이 다음 사람에게 남기는 부탁 ──────────────
create table if not exists public.messages (
  id          bigint generated by default as identity primary key,
  text        text not null check (char_length(trim(text)) between 1 and 80),
  created_at  timestamptz not null default now()
);

-- 새 버전에서 추가된 컬럼 (이미 있으면 무시됨)
alter table public.messages add column if not exists author     text;
alter table public.messages add column if not exists claimed_by text;
alter table public.messages add column if not exists claimed_at timestamptz;
-- 남긴 사람이 고른 캐릭터. 다음 사람의 화면에서 쓰러져 있는 모습이 이 캐릭터로 그려진다
alter table public.messages add column if not exists char_index int;

-- 아직 아무도 받아가지 않은 부탁을 빠르게 찾기 위한 인덱스
create index if not exists messages_unclaimed_idx
  on public.messages (created_at) where claimed_by is null;
create index if not exists messages_author_idx on public.messages (author);

alter table public.messages enable row level security;

drop policy if exists "anyone can read messages" on public.messages;
create policy "anyone can read messages"
  on public.messages for select to anon using (true);

drop policy if exists "anyone can leave a message" on public.messages;
create policy "anyone can leave a message"
  on public.messages for insert to anon with check (true);
```

```sql
-- ── message_boosts: 죽였는지 살렸는지의 판정 기록 ────────────────
-- (이전 버전의 "힘이 나요" 테이블을 그대로 재사용합니다)
create table if not exists public.message_boosts (
  id            bigint generated by default as identity primary key,
  message_text  text not null check (char_length(trim(message_text)) between 1 and 80),
  created_at    timestamptz not null default now()
);

alter table public.message_boosts add column if not exists message_id bigint;
alter table public.message_boosts add column if not exists judge      text;
alter table public.message_boosts add column if not exists verdict    text
  check (verdict in ('killed','spared'));

create index if not exists message_boosts_message_id_idx
  on public.message_boosts (message_id);

alter table public.message_boosts enable row level security;

drop policy if exists "anyone can read boosts" on public.message_boosts;
create policy "anyone can read boosts"
  on public.message_boosts for select to anon using (true);

drop policy if exists "anyone can add a boost" on public.message_boosts;
create policy "anyone can add a boost"
  on public.message_boosts for insert to anon with check (true);
```

정책의 의미는 두 테이블 모두 동일합니다.

- `select` + `insert` 만 허용 → **읽기와 남기기만** 가능
- `update` / `delete` 정책 없음 → 남의 기록을 **고치거나 지울 수 없음**
- `check (char_length ...)` → 빈 메시지·초장문 스팸을 DB 단에서 차단

## 2단계 — 메시지를 "정확히 한 번만" 배정하는 함수

이 게임은 **한 사람이 남긴 부탁을 딱 한 사람만** 받도록 되어 있습니다. 그냥 `SELECT` 로 뽑으면
동시에 접속한 두 명이 같은 부탁을 받아버리므로, Postgres의 큐 패턴(`FOR UPDATE SKIP LOCKED`)을
쓰는 함수를 만들어 원자적으로 배정합니다.

```sql
create or replace function public.claim_message(p_nickname text)
returns table (id bigint, text text, author text, char_index int)
language plpgsql
security definer            -- 플레이어에겐 UPDATE 권한이 없으므로 함수가 대신 수행
set search_path = public
as $$
begin
  return query
  update public.messages m
     set claimed_by = p_nickname,
         claimed_at = now()
   where m.id = (
     select m2.id
       from public.messages m2
      where m2.claimed_by is null
        and m2.author is distinct from p_nickname   -- 자기 부탁은 자기가 못 받게
      order by m2.created_at
      limit 1
      for update skip locked                        -- 동시 접속해도 중복 배정 없음
   )
  returning m.id, m.text, m.author, m.char_index;
end;
$$;

revoke all on function public.claim_message(text) from public;
grant execute on function public.claim_message(text) to anon;
```

`skip locked` 덕분에 두 명이 같은 순간에 요청해도 서로 다른 행을 받습니다. 남은 부탁이 없으면
아무 행도 반환하지 않고, 그때는 게임이 코드에 하드코딩된 시드 문장으로 조용히 대체합니다
(플레이어에게는 티가 나지 않지만, 마지막 화면에서는 정직하게 "당신이 첫 번째"라고 알려줍니다).

## 3단계 — 키 넣기

**Project Settings → API** 에서 두 값을 복사해 `game.js` 상단에 넣습니다.

```js
const SUPABASE_URL = "https://abcdefgh.supabase.co";   // Project URL
const SUPABASE_ANON_KEY = "eyJhbGciOi...";             // anon public 키
```

> ⚠️ `service_role` 키는 **절대** 쓰지 마세요. 모든 권한을 가진 비밀 키라서 페이지에 넣으면
> 누구나 꺼내서 DB 전체를 조작할 수 있습니다. `anon` 키는 원래 공개용이라 페이지에 포함되는
> 게 정상입니다.

## 4단계 — GitHub Pages에 올리기

1. 저장소 루트에 `index.html`, `game.js`, `style.css`, `assets/` 를 모두 올립니다
   (`assets/` 안의 이미지가 빠지면 화면이 검게 나옵니다)
2. **Settings → Pages** → Source `Deploy from a branch`, Branch `main` / `/ (root)`
3. 1~2분 후 `https://<사용자명>.github.io/<저장소명>/` 이 열립니다 — 이 링크를 공유하세요

`devserver.py` 와 `.shots/` 는 로컬 테스트용이라 올리지 않아도 됩니다.

## 확인 방법

1. 배포된 링크에서 한 판을 끝까지 진행하고 마지막에 부탁을 남깁니다
2. Supabase **Table Editor → messages** 에 `author` 와 함께 새 행이 보이는지 확인
3. **다른 브라우저(또는 시크릿 창)** 로 열어 다른 닉네임으로 플레이 → 출구 앞에서
   1번에서 남긴 그 문장이 나오는지 확인
4. 그 판에서 죽이거나 살린 뒤, **message_boosts** 에 `verdict` 가 기록됐는지 확인
5. 다시 1번 닉네임으로 플레이하면 마지막 화면에 "OOO이 그 말을 들었고, 당신을 …" 이 뜹니다

문제가 생기면 브라우저 콘솔을 보세요.

| 콘솔 메시지 | 원인 |
|---|---|
| `rpc 404` | 2단계의 `claim_message` 함수를 안 만들었음 (시드 문장으로 폴백됨) |
| `insert 400` | `messages.author` 컬럼이 없음 → 1단계 `alter table` 재실행 |
| `401` / `403` | 키가 틀렸거나 RLS 정책이 빠짐 |

## 운영 시 알아둘 것

- **⚠️ 메시지 필터링이 없습니다.** 현재 욕설·스팸 필터를 넣지 않았습니다. `game.js` 의
  `sanitize()` 가 훅 자리로 비어 있으니 필요하면 여기에 추가하세요.
  이 장르의 대표작 [Moirai](https://en.wikipedia.org/wiki/Moirai_(video_game)) 는
  응답의 53%에 욕설이 섞였고, 결국 한 명이 스크립트로 DB를 플러딩해 **2017년 영구 종료**했습니다.
  `anon` 키는 페이지에 노출되므로 구조적으로 같은 공격이 가능합니다.
- **부적절한 메시지 삭제**: **Table Editor → messages** 에서 해당 행을 지우면 됩니다.
  `anon` 키로는 삭제가 불가능하므로 대시보드에서만 가능합니다.
  이미 누군가에게 배정된 뒤라면 늦으니, 행사 중에는 가끔 확인하는 게 좋습니다.
- **비상시 전체 초기화**: 0단계의 `truncate` 두 줄을 다시 실행하면 됩니다.
- **오프라인/장애 시에도 게임은 돌아갑니다.** 공유 저장소를 못 쓰면 로컬 저장소 → 시드 문장
  순으로 대체되고, 남긴 부탁은 항상 로컬에도 복사됩니다.
