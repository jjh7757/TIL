## 슬라이드 1 — 문제

### 화면에 넣을 내용

```
모의투자를 처음 시작한 사람은
숫자를 보지만 무엇을 봐야 할지 모릅니다

PER 12.3 · 평가손익 -32,000원 · 이동평균선 하회
                    ↓
            그래서 어떻게 하라고?

결과: 판단을 미루거나, 근거 없이 감으로 매매
```

### 발표자 노트 (약 22초)

> 모의투자 계좌를 처음 열면 화면에 숫자는 많은데, 그게 무슨 의미인지 알 수 없습니다. PER이 12.3이라는 게 좋은 건지 나쁜 건지 모릅니다. 그래서 초보 투자자는 판단을 미루거나, 아무 근거 없이 감으로 매매합니다. 이 프로젝트는 그 문제를 다룹니다.

## 슬라이드 2 — 목표를 "수익"으로 잡지 않은 이유

### 화면에 넣을 내용

```
처음 세운 목표:  모의투자로 안정적인 수익
                    ↓ 폐기

  통제 불가      시장이 하락하면 시스템이 완벽해도 실패
  검증 불가      "안정적"은 수개월 데이터 필요
  층위 불일치    문제는 '이해', 목표는 '성과'
  설계 왜곡      수익을 걸면 종목 추천기가 됨

확정한 목표:  매매 1건마다 판단 근거를 스스로 설명할 수 있다
```

### 발표자 노트 (약 25초)

> 처음에는 목표를 "안정적인 수익"으로 잡았습니다. 그런데 이건 시장이 결정하는 거라 제가 통제할 수 없고, 5일 안에 검증도 안 됩니다. 무엇보다 문제는 "이해"인데 목표가 "성과"여서 서로 연결되지 않았습니다. 수익을 목표로 걸면 시스템이 종목 추천기로 끌려가는데, 그건 유사투자자문 영역입니다. 그래서 목표를 문제와 같은 층위로 바꿨습니다 — **판단 근거를 스스로 설명할 수 있는가.**

> 💡 **이 슬라이드가 발표의 핵심입니다.** 기능을 자랑하는 발표는 많지만, 목표를 스스로 폐기하고 다시 세운 과정을 보여주는 발표는 드뭅니다.

## 슬라이드 3 — 해결 방식

### 화면에 넣을 내용

```
텔레그램에서 자연어로 대화합니다

  "PER이 뭐야?"        → 초보자 언어로 용어 설명
  "내 계좌 어때?"       → 숫자를 해석 문장으로
  "삼성전자 어때?"      → 시세 + 지표의 의미
  "삼성전자 10주 사줘"  → 확인 → 근거 입력 → 주문

AI가 하지 않는 것
  종목 추천 ✗   수익 예측 ✗   종목코드 생성 ✗   금액 계산 ✗
```

### 발표자 노트 (약 22초)

> 텔레그램에서 자연어로 물으면 됩니다. 슬래시 명령어는 없습니다. 용어를 물으면 초보자 언어로 설명하고, 계좌를 물으면 숫자를 해석 문장으로 바꿔줍니다. 중요한 건 AI가 하지 않는 것입니다. 종목 추천과 수익 예측은 하지 않고, 종목코드와 금액 계산도 AI에 맡기지 않습니다. **LLM이 만든 값을 주문에 바로 쓰지 않습니다.**

## 슬라이드 4 — 핵심: 주문 전에 근거를 받습니다

### 화면에 넣을 내용

```
"삼성전자 10주 사줘"
    ↓
"10주, 약 74만원입니다. 진행하시겠습니까?"     ← 확인
    ↓ "네"
"매수 이유를 골라주세요"                       ← 근거 입력
  저평가 / 실적개선 / 업황 / 뉴스 / 배당 / 그냥 감
    ↓ "실적 개선"
주문 접수 · 근거 저장

────────────────────────────────────
근거가 저장되기 전에는 주문이 나가지 않습니다
```

### 발표자 노트 (약 25초)

> 이 프로젝트에서 새로 만든 건 이 단계입니다. 주문을 실행하기 **전에** 판단 근거를 받습니다. 주문 후에 물으면 사용자가 이탈하니까요. 그리고 주문 직전에 이유를 말하게 만들면 **판단을 한 번 더 점검하게 됩니다.** 선택지에 `그냥 감`을 일부러 넣었습니다. 없으면 아무거나 고르고 데이터가 오염되니까요. `그냥 감` 비율 자체가 지표가 됩니다.

## 슬라이드 5 — 이미 있던 것과 새로 만든 것

### 화면에 넣을 내용

```
이미 있었음 (n8n)                     이번에 만든 것
─────────────────────         ─────────────────────
KIS 토큰 발급/갱신                    의도 분류 (자연어 → 요청)
모의계좌 잔고조회                     종목명 → 종목코드 변환
시세조회                              주문 확인 단계
모의 매수/매도 주문                   ★ 판단 근거 기록
텔레그램 · LLM · Supabase             예외 처리 11종

기존: 명령을 주면 기능이 각각 동작
이번: 대화 한 번이 하나의 판단 과정으로 이어지고, 그 근거가 남는다
```

### 발표자 노트 (약 23초)

> KIS 연동은 이미 n8n으로 만들어 둔 상태였습니다. 그래서 이번 프로젝트는 만드는 게 아니라 **연결하는** 프로젝트였습니다. 기존에는 명령을 주면 기능이 각각 동작했는데, 이번에는 대화 한 번이 하나의 판단 과정으로 이어집니다. 그리고 그 판단의 근거가 남습니다. **판단 근거는 어디에도 존재하지 않던 데이터입니다.**

## 슬라이드 6 — 결과와 한계

### 화면에 넣을 내용

```
확인한 것
  테스트 사용자 2명 × 3회 매매 = 6건, 전부 근거 기록
  '그냥 감' 선택 6건 중 O건
  의도 분류 테스트 표현 20개 중 O개 정확
  예외 흐름 11개 전부 동작 확인

확인하지 못한 것
  표본 6건은 통계가 아닙니다 — 가정은 여전히 가정입니다
  대화 맥락("그거 10주") 미구현 · 체결 확인 범위 밖
  의도 오분류 시 확인 단계가 유일한 방어선

다음: 사용자 수를 늘려 '근거를 말할 수 있는가'를 실제로 검증
```

### 발표자 노트 (약 25초)

> 테스트 사용자 2명이 각각 3회 매매했고, 6건 모두 근거가 기록됐습니다. 다만 **6건은 통계가 아닙니다.** 그래서 "가정이 검증됐다"고 말하지 않겠습니다. 방향이 가능해 보인다는 것까지입니다. 한계도 있습니다. `그거 10주 사줘` 같은 대화 맥락은 못 만들었고, 체결 확인은 범위 밖으로 뒀습니다. 다음 단계는 사용자를 늘려서 실제로 근거를 말할 수 있게 되는지 확인하는 것입니다.

> 🔴 **`O`에 실제 숫자를 채우십시오.** Day 4~5에 측정 SQL을 돌린 결과를 넣습니다.

## 🔴 시연 계획

### 시연 순서 — 의존성이 낮은 것부터

```
1. "PER이 뭐야?"        ← KIS에 의존하지 않음. 가장 안전
2. "내 계좌 어때?"       ← 잔고조회만 필요
3. "삼성전자 어때?"      ← 시세조회만 필요
4. "삼성전자 10주 사줘"  ← 전부 필요 + 장 시간 제약
```

**뒤에서 터져도 앞은 이미 보여준 상태가 됩니다.** 반대로 주문부터 보여주다 실패하면 아무것도 못 보여줍니다.

### 발표 시각에 따른 분기

| 발표 시각 | 시연 방법 |
|---|---|
| 월 09:00~15:30 | 1~4 전부 라이브. 실패하면 즉시 영상으로 전환 |
| 그 외 | 1~3 라이브, **4는 Day 3(금)에 녹화한 영상** |

> 🔴 **발표 시각을 미리 확인하십시오.** 장 시간 밖이면 주문 라이브는 불가능합니다.

### 시연 전 확인 사항

- [ ] Day 3(금)에 녹화한 주문 시연 영상을 재생 가능한 상태로 준비
- [ ] 영상과 화면에 **계좌번호·`chat_id`·토큰값이 보이지 않음**
- [ ] 예수금이 충분한 상태 (주문 라이브 시)
- [ ] 진행 중인 대기 주문이 없는 상태 (있으면 중복 차단됨)
- [ ] 텔레그램 대화창을 미리 열어 두고 글자 크기 확대
