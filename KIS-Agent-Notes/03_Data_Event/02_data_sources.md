# 데이터 소스

- 작성일: 2026-08-04
- 근거 교안: 4교시

---

## 1. 데이터 소스란?

데이터가 **처음 발생하거나 프로젝트 시스템으로 들어오는 곳**입니다.

데이터 소스를 정리하면 다음을 판단할 수 있습니다.

- 어떤 데이터가 우리 책임이고 어떤 데이터가 외부 책임인가
- 외부가 응답하지 않을 때 무엇이 멈추는가
- 저장해야 하는 데이터와 매번 가져와야 하는 데이터가 무엇인가

---

## 2. 데이터 소스표

| 데이터 | 처음 발생하는 곳 | 사용하는 이유 | 저장 여부 |
|---|---|---|---|
| 사용자 메시지 원문 | 텔레그램 | 의도 분류의 입력 | 맥락 1건만 |
| `chat_id` | 텔레그램 | 사용자 식별, 화이트리스트 검증 | ✅ |
| 근거 선택지 응답 | 텔레그램 (인라인 키보드) | 판단 근거 유형 기록 | ✅ |
| 근거 메모 | 사용자 입력 | 판단 근거 상세 기록 | ✅ |
| 확인 응답 (`네`/`아니요`) | 사용자 입력 | 주문 실행 여부 결정 | ❌ (이벤트만) |
| 의도 · 종목명 · 수량 | LLM 의도 분류 | 흐름 분기와 주문 파라미터 | ❌ (이벤트만) |
| 용어 설명문 | LLM | 초보자에게 용어 해설 제공 | ❌ (이벤트만) |
| 계좌 상황 해석문 | LLM | 숫자를 읽을 수 있는 문장으로 변환 | ❌ (이벤트만) |
| 시세 해석문 | LLM | 지표의 의미 설명 | ❌ (이벤트만) |
| 종목코드 · 종목명 · 시장구분 | 종목 마스터 (사전 적재) | 종목명 → 종목코드 변환 | ✅ |
| KIS 접근토큰 | KIS 인증 API | 모든 KIS 호출의 전제 | ❌ (Credential) |
| 예수금 · 보유종목 · 평균단가 · 수익률 | KIS 잔고조회 | 계좌 상황 진단, 예수금 검증 | ❌ |
| 현재가 · 등락률 · 거래량 | KIS 시세조회 | 종목 해석, 예상 금액 계산 | ❌ |
| 주문번호 · 주문결과 | KIS 주문 API | 주문 성공·실패 판단 | ✅ |
| 체결 결과 | KIS 주문·체결 조회 | 체결 여부 안내 | ✅ |
| 주문 상태 변화 | 우리 시스템 | 흐름 제어 | ✅ |
| 이벤트 기록 | 우리 시스템 | 성공 기준 측정, 오류 분석 | ✅ |

## 3. 소스별 정리

### 3.1 텔레그램 (외부)

우리가 통제하지 않는 입력이 들어오는 유일한 창구입니다.

**들어오는 것**: 메시지 원문, `chat_id`, 인라인 키보드 선택

**위험**: 누구나 메시지를 보낼 수 있습니다. 따라서 **`chat_id` 화이트리스트가 첫 관문**입니다. 화이트리스트를 통과하지 못한 메시지는 어떤 데이터로도 취급하지 않습니다.

### 3.2 LLM (외부)

**들어오는 것**: 의도 분류 결과, 용어·계좌·시세 해석문

**중요**: LLM은 데이터를 *만들어냅니다*. 조회한 게 아닙니다. 따라서 다음 원칙을 적용합니다.

| 원칙 | 이유 |
|---|---|
| 종목코드를 LLM이 생성하게 하지 않습니다 | 존재하지 않는 코드를 만들 수 있습니다. **종목 마스터 조회로만 확정합니다.** |
| 가격·수익률을 LLM이 계산하게 하지 않습니다 | 숫자를 틀릴 수 있습니다. 계산은 코드가 하고 LLM은 설명만 합니다. |
| 매수·매도 권유를 생성하지 않게 합니다 | 유사투자자문 위험. 프롬프트에 명시적으로 금지합니다. |
| 수량은 LLM이 추출하되 코드가 검증합니다 | 추출은 자연어 처리이지만, 음수·0·과도한 수량은 코드로 막습니다. |

> **LLM이 만든 값은 주문 파라미터로 바로 쓰지 않습니다.** 종목코드는 마스터에서, 금액은 시세에서, 검증은 코드에서 확정합니다.

### 3.3 종목 마스터 (사전 적재)

**유일하게 우리가 미리 준비해야 하는 기준 데이터입니다.**

| 항목 | 내용 |
|---|---|
| 적재 시점 | 개발 초기 1회 |
| 적재 범위 | 코스피200 등 상위 200종목 (6교시에서 확정) |
| 갱신 주기 | 이번 프로젝트에서는 갱신하지 않습니다 (5일) |
| 목록 밖 종목 | `지원하지 않는 종목입니다`로 안내 |

> 이 데이터가 없으면 **흐름 C(시세 조회)와 흐름 D(주문)가 전부 막힙니다.** 사용자는 종목명으로 말하기 때문입니다. 따라서 WBS에서 가장 앞에 배치해야 하는 작업입니다.

### 3.4 KIS 모의투자 시스템 (외부)

이미 n8n 서브워크플로우로 연동이 끝난 부분입니다.

| 서브워크플로우 | 제공하는 데이터 |
|---|---|
| KIS 토큰 발급/갱신 | 접근토큰 |
| 모의계좌 잔고조회 | 예수금, 보유종목, 평균단가, 평가금액, 수익률 |
| 시세조회 | 현재가, 등락률, 거래량 |
| 모의 매수/매도 주문 | 주문번호, 주문결과 |

**KIS가 응답하지 않으면 멈추는 것**

| KIS 장애 | 영향 |
|---|---|
| 토큰 발급 실패 | **모든 KIS 기능 정지.** 용어 설명(흐름 A)만 계속 동작합니다. |
| 잔고조회 실패 | 계좌 진단 불가, 예수금 검증 불가 → 주문도 차단 |
| 시세조회 실패 | 종목 해석 불가, 예상 금액 계산 불가 → 주문도 차단 |
| 주문 실패 | 주문만 불가. 조회 기능은 계속 동작 |

> **흐름 A(용어 설명)는 KIS에 의존하지 않습니다.** 발표 당일 KIS 장애가 나도 이 흐름은 시연할 수 있습니다. 시연 순서를 짤 때 이 사실을 활용합니다 — 의존성이 낮은 흐름부터 보여줍니다.

### 3.5 우리 시스템 (Supabase)

**우리가 처음 만들어내는 데이터**는 3가지뿐입니다.

| 데이터 | 왜 우리가 만드는가 |
|---|---|
| 주문 상태 | KIS는 주문 접수 결과만 줍니다. 확인 대기·근거 대기 같은 **대화 단계는 우리만 압니다.** |
| 판단 근거 | 어디에도 존재하지 않던 데이터입니다. **이 프로젝트가 새로 만들어내는 유일한 가치.** |
| 이벤트 기록 | 성공 기준을 측정하기 위해 우리가 남깁니다. |

## 4. 데이터 유형 분류

교안 4교시의 분류를 적용합니다.

| 유형 | 해당 데이터 |
|---|---|
| **기준 정보** | 종목 마스터, 근거 유형 선택지 |
| **거래 정보** | 주문, 체결 |
| **상태 정보** | 주문 상태, 대화 맥락, 토큰 상태 |
| **사건 기록** | 이벤트 로그 (도메인 이벤트 + 운영 로그) |
| **개인정보** | `chat_id`, 계좌번호 |
| **참조 정보** (저장 안 함) | 예수금, 보유종목, 시세 |

> 마지막 `참조 정보`는 교안에 없는 분류를 추가한 것입니다. **외부에서 매번 가져오고 저장하지 않는 데이터**를 구분해야 "왜 DB에 잔고 테이블이 없느냐"는 질문에 답할 수 있습니다.

## 5. 데이터 흐름 요약

```
텔레그램 (메시지)
→ chat_id 화이트리스트 검증
→ LLM 의도 분류 (의도·종목명·수량 추출)
→ 종목 마스터 조회 (종목명 → 종목코드 확정)
→ KIS 조회 (시세·잔고)
→ 코드 검증 (예수금·수량·장 시간)
→ 사용자 확인
→ 판단 근거 입력 (Supabase 저장)
→ KIS 주문
→ 결과 저장 및 안내
→ 이벤트 기록
```

상세 다이어그램은 5교시 단계의 [[../04_Architecture/01_data_flow|데이터 흐름]] 문서에서 작성합니다.
