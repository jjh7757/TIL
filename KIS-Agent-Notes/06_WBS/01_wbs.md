## 1. 문서 목적

6교시에서 확정한 MVP 범위(Must)를 **실제로 수행할 수 있는 작업 단위로 나누기 위해** 작성합니다.

### 혼자 하는 프로젝트에서 선행 작업의 의미

교안은 팀 프로젝트를 전제하므로 선행 작업을 **담당자별 병렬 배분**에 씁니다. 이 프로젝트는 혼자이므로 모든 작업이 순차 실행됩니다.

그래서 선행 작업을 다른 용도로 씁니다.

```
선행 작업 = 순서를 틀리면 되돌아가서 다시 해야 하는 지점
```

예를 들어 `chat_id` 버그를 고치기 전에 중복 방지 인덱스를 만들면, 모든 행의 `chat_id`가 같은 문자열이라 두 번째 주문부터 전부 차단됩니다. **인덱스를 지우고 다시 만들어야 합니다.** 이런 되돌아감을 막는 것이 이 표의 목적입니다.

## 4. 임계 경로

되돌아갈 수 없는 최장 연쇄입니다. 이 경로가 늦어지면 전체가 늦어집니다.

```
1.3 발신자 검증 (0.5h)
→ 2.1 의도 분류 (4h)
→ 2.2 종목코드 변환 (2h)
→ 3.3 시세 해석 (1.5h)
→ 4.1 사전 검증 (2h)
→ 4.2 주문 확인 (2h)
→ 4.3 근거 입력 (3h)
→ 4.5 실패 분기·만료 (1.5h)
→ 5.1 이벤트 기록 (2h)
→ 6.1 통합 테스트 (3h)
→ 6.2 시연 녹화 (0.5h)

= 22h
```

### 임계 경로에서 읽어야 할 것

**2.1 의도 분류(4h)가 임계 경로의 최대 단일 작업입니다.** 여기가 막히면 아래 전부가 멈춥니다. 조회 흐름 3개(3.1·3.2·3.3)도 모두 2.1에 의존합니다.

→ **2.1을 Day 1에 배치합니다.** 막힐 가능성이 가장 큰 작업을 가장 이른 시점에 둡니다. Day 4에 막히면 되돌릴 시간이 없습니다.

임계 경로에 없는 작업(1.1·1.2·1.5·1.6·3.1·3.2·4.4·7.1·7.2)은 순서를 조정할 여지가 있습니다. **일정이 밀리면 이쪽을 뒤로 미룹니다.**

## 5. 기능별 인수 조건

### 의도 분류

- [ ] 테스트 표현 20개 중 18개 이상을 올바른 의도로 분류합니다.
- [ ] `음...` 같은 메시지에 가능한 기능 목록이 안내됩니다.
- [ ] `네`·`응`·`좋아`·`진행해`가 모두 `confirm`으로 분류됩니다.
- [ ] `아니요`·`취소`·`됐어`가 모두 `cancel`로 분류됩니다.
- [ ] 판별 실패 시 원문이 `event_logs`에 남습니다.

> 3·4번째 항목이 중요합니다. 확인 단계에서 문자열 비교로는 `ㅇㅇ`을 잡을 수 없습니다.

### 종목 해석

- [ ] `삼성전자`가 `005930`으로 변환됩니다.
- [ ] `삼성전자` 조회 시 `삼성전자`·`삼성전자우`가 후보로 제시됩니다.
- [ ] 후보가 여러 개일 때 **주문이 진행되지 않습니다.**
- [ ] 목록에 없는 종목명에 안내가 표시되고 중단됩니다.

### 조회 흐름

- [ ] 용어 질문에 초보자 수준의 설명이 표시됩니다.
- [ ] 초보자 3명이 설명을 읽고 용어를 자기 말로 다시 설명할 수 있습니다.
- [ ] 계좌 질문에 해석 문장이 표시됩니다.
- [ ] 시세 질문에 현재가와 지표 설명이 표시됩니다.
- [ ] 응답 30건에 매수·매도 권유 표현이 0건입니다.
- [ ] **토큰 테이블을 비운 상태에서 용어 설명이 동작합니다.**

### 주문 흐름

- [ ] **확인 동의 전에 KIS 주문이 호출되지 않습니다.**
- [ ] **근거 저장 전에 KIS 주문이 호출되지 않습니다.**
- [ ] 확인을 거부하면 `cancelled`가 되고 KIS가 호출되지 않습니다.
- [ ] 근거 선택지 6개가 인라인 키보드로 표시됩니다.
- [ ] 메모를 건너뛰어도 주문이 진행됩니다.
- [ ] 장 마감 시 주문이 차단되고 조회는 동작합니다.
- [ ] 예수금 부족 시 잔액과 필요 금액이 안내됩니다.
- [ ] 진행 중 주문이 있으면 새 주문이 차단됩니다.
- [ ] 주문 성공 시 기존 행이 UPDATE되고 새 행이 추가되지 않습니다.
- [ ] 주문 거부 시 사유가 안내되고 `rationales`가 보존됩니다.
- [ ] 10분 후 만료되며, 만료 후 `네`는 주문을 실행하지 않습니다.

### 측정

- [ ] 정상 주문 1건에서 도메인 이벤트 5개가 기록됩니다.
- [ ] 측정 지표 4개를 각각 SQL 한 번으로 산출할 수 있습니다.

## 6. 팀 완료의 정의

혼자 하는 프로젝트이지만 모든 작업에 공통 적용합니다.

- [ ] 작업의 완료 조건을 만족합니다.
- [ ] **정상 상황과 실패 상황을 모두 확인했습니다.**
- [ ] 변경한 데이터·이벤트·상태를 관련 문서에 반영했습니다.
- [ ] 문서와 구현이 일치합니다. (다르면 문서를 고칩니다)
- [ ] 개인정보와 자격증명이 노출되지 않습니다.
- [ ] 다른 사람이 같은 방법으로 완료 여부를 확인할 수 있습니다.

> **예외 흐름 11개 중 8개가 주문 흐름**입니다. 정상 흐름만 확인하고 완료로 판단하면 발표 시연에서 터집니다.
