## 1. 사용자 역할표

교안 3교시의 정의에 따라, 사용자 역할은 **사람뿐 아니라 외부 시스템도 포함**합니다.

| 역할 | 주요 책임 | 주요 행동 | 접근 데이터 |
|---|---|---|---|
| **투자자** | 매매를 판단하고 근거를 기록합니다. | 용어 질문, 계좌 조회 요청, 시세 조회 요청, 주문 요청, 주문 확인, 근거 입력 | 자신의 계좌·보유종목·주문·근거 기록 |
| **AI 설명 에이전트** | 용어와 데이터를 초보자 언어로 해석합니다. | 용어 설명, 계좌 상황 진단, 시세 해석, 전략 유형 설명 | 조회된 계좌·시세 데이터, 대화 맥락 |
| **대화 오케스트레이터** | 의도를 판별하고 흐름을 제어합니다. | 의도 분류, 종목명 해석, 서브워크플로우 호출, 확인 단계 관리, 상태 저장 | 대화 맥락, 주문 대기 상태, 의도 분류 결과 |
| **KIS 모의투자 시스템** (외부) | 계좌·시세를 제공하고 주문을 접수·체결합니다. | 토큰 발급, 잔고 응답, 시세 응답, 주문 결과 반환 | KIS 측 계좌·주문·체결 데이터 |
| **텔레그램** (외부) | 메시지를 전달합니다. | 메시지 수신, 메시지 발신, 인라인 키보드 표시 | 메시지 본문, `chat_id` |
| **운영자** | 워크플로우를 운영하고 오류를 확인합니다. | 실행 로그 확인, 워크플로우 수정, 종목 마스터 갱신 | 실행 기록, 오류 로그, 종목 마스터 |

## 2. 사용자와 역할의 차이

이번 프로젝트는 **본인 단일 사용자**입니다. 즉 `투자자`와 `운영자`는 같은 사람입니다.

그런데도 역할을 나눈 이유는 교안 3교시의 원칙 때문입니다.

> 사용자는 실제 사람이나 시스템이고, 역할은 그 사용자가 맡은 책임입니다.
> 한 사람이 두 역할을 겸할 수 있지만, 시스템에서는 두 역할의 권한을 구분해야 합니다.

역할을 나눠 두면 다음이 명확해집니다.

- **투자자**가 하는 행동은 텔레그램 대화로만 이루어집니다. n8n 관리 화면을 열지 않습니다.
- **운영자**가 하는 행동은 n8n 관리 화면에서만 이루어집니다. 텔레그램에 운영 명령을 넣지 않습니다.
- 따라서 **텔레그램에서 워크플로우를 수정하거나 종목 마스터를 갱신하는 기능은 만들지 않습니다.**

## 3. 권한

이번 프로젝트는 단일 사용자이므로 복잡한 권한 체계는 만들지 않습니다. 다만 **한 가지는 반드시 필요합니다.**

### 🔴 텔레그램 발신자 제한 (Must)

```
등록된 chat_id에서 온 메시지만 처리합니다.
등록되지 않은 chat_id는 응답 없이 무시합니다.
```

**왜 필수입니까?**

| 이유 | 설명 |
|---|---|
| 봇은 누구나 찾을 수 있습니다 | 텔레그램 봇 사용자명을 알면 아무나 메시지를 보낼 수 있습니다. |
| 주문은 되돌릴 수 없습니다 | 제3자가 `삼성전자 100주 사줘`를 보내면 본인 계좌에 실제로 모의 주문이 들어갑니다. |
| 발표 중 난입 위험 | 시연 도중 다른 사람이 메시지를 보내면 데모가 망가집니다. |
| 근거 데이터 오염 | 남이 넣은 주문에는 근거가 없어 성공 기준 측정값이 왜곡됩니다. |

모의투자라서 금전 피해는 없지만, **위 4가지는 모의투자에서도 그대로 발생합니다.** 따라서 `chat_id` 화이트리스트는 `Should`가 아니라 `Must`입니다.

### 자격증명 관리

교안 8교시의 API Key 관리 원칙을 적용합니다.

| 대상 | 관리 방법 |
|---|---|
| KIS 앱키·시크릿 | n8n Credential에 저장. 워크플로우 JSON에 직접 쓰지 않습니다. |
| 텔레그램 봇 토큰 | n8n Credential에 저장 |
| LLM API 키 | n8n Credential에 저장 |
| 계좌번호 | 환경변수 또는 Credential. 문서·발표자료에 노출하지 않습니다. |
| GitHub 업로드 시 | 워크플로우 JSON을 내보낼 때 Credential 값이 포함되지 않았는지 확인. `.gitignore` 설정 |

> ⚠️ 발표자료와 시연 영상에 **계좌번호와 실행 로그의 토큰값이 노출되지 않도록** 가려야 합니다.

## 4. 확장 시 추가될 역할 (이번 범위 밖)

| 역할 | 언제 필요해지는가 |
|---|---|
| 다수 투자자 | 사용자별 KIS 계좌 매핑이 필요해질 때 |
| 관리자 | 사용자 관리·이용 지표 확인이 필요해질 때 |

이번 프로젝트에서는 만들지 않습니다. 다만 데이터 구조에 `user_id`를 남겨 두어 나중에 확장할 수 있게 합니다.
