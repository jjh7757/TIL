# 도메인 정의와 도메인 요소

- 작성일: 2026-08-04
- 근거 교안: 3교시

---

## 1. 도메인 정의

```
모의투자 계좌를 사용하는 초보 투자자가
투자용어와 계좌·종목 정보를 이해하고,
판단 근거를 남기면서 모의 매매를 실행하는 업무
```

### 프로젝트와 도메인의 구분

교안 3교시의 구분을 이 프로젝트에 적용하면 다음과 같습니다.

```
프로젝트
→ 5일 안에 텔레그램 AI 에이전트를 설계하고 기존 n8n 기능을 연계하는 개발 활동

도메인
→ 모의투자 계좌에서 종목을 조회하고 판단하고 주문하고 근거를 남기는 업무

도메인 요소
→ 그 업무에 필요한 사용자, 계좌, 종목, 시세, 주문, 근거, 상태와 사건

화면
→ 텔레그램 대화창 (별도 화면 없음)

버튼
→ 근거 선택지 버튼, 주문 확인 버튼 (텔레그램 인라인 키보드)
```

> 이 프로젝트에는 웹 화면이 없습니다. **대화가 화면입니다.** 따라서 일반적인 화면 설계 대신 **대화 흐름 설계**가 그 자리를 대신합니다.

## 2. 주요 도메인 요소

| 도메인 요소 | 설명 | 코드 이름 예시 |
|---|---|---|
| 사용자 | 텔레그램으로 대화하는 초보 투자자 | `User` |
| 모의투자 계좌 | KIS 모의투자 계좌. 예수금과 보유 종목을 가짐 | `Account` |
| 보유 종목 | 계좌가 보유한 종목의 수량·평균단가·평가금액·수익률 | `Holding` |
| 종목 | 거래 가능한 상장 종목. 종목명과 종목코드를 가짐 | `Stock` |
| 시세 | 종목의 현재가·등락률·거래량 | `Quote` |
| 투자용어 | 설명 대상이 되는 용어와 지표 | `Term` |
| 대화 세션 | 멀티턴 맥락을 담는 대화 단위 | `Conversation` |
| 의도 | 사용자 메시지에서 해석한 요청의 종류 | `Intent` |
| 주문 | 모의 매수·매도 요청 | `Order` |
| 체결 | 주문이 실제로 성립된 결과 | `Execution` |
| **판단 근거** | 주문 시 사용자가 입력한 매매 이유 | `Rationale` |
| 접근토큰 | KIS API 호출에 사용하는 인증 토큰 | `AccessToken` |

### 이 프로젝트에서 특별한 요소: 판단 근거

`판단 근거`는 일반적인 투자 서비스에 없는 도메인 요소입니다. 이 프로젝트의 **성공 기준을 측정하는 유일한 대상**이기 때문에 1급 도메인 요소로 취급합니다.

```
판단 근거가 없으면
→ 저장할 데이터가 없고
→ 기록할 이벤트가 없고
→ 성공 기준을 측정할 방법이 없고
→ 발표에서 보여줄 결과가 없습니다.
```

## 3. 도메인 요소가 개발로 연결되는 과정

교안 3교시의 연결 표를 이 프로젝트의 핵심 요소 3개에 적용합니다.

### 3.1 주문

| 연결 대상 | 필요한 내용 |
|---|---|
| 데이터 | 주문번호, 종목코드, 매수·매도 구분, 수량, 가격, 주문상태, 주문시각 |
| 대화 | 주문 요청 → 확인 → 근거 입력 → 결과 안내 (4턴) |
| 기존 자산 | `모의 매수/매도 주문` 서브워크플로우 ✅ |
| 새로 만들 것 | 확인 단계, 중복 주문 방지, 근거 입력 연결 |
| 이벤트 | `order_requested`, `order_confirmed`, `order_submitted`, `order_rejected`, `order_executed` |
| 테스트 | 정상 매수, 예수금 부족, 장 마감, 주문 거부, 확인 단계 이탈 |

### 3.2 종목

| 연결 대상 | 필요한 내용 |
|---|---|
| 데이터 | 종목코드, 종목명, 시장구분 |
| 대화 | 사용자가 종목명으로 말함 → 종목코드로 변환 |
| 기존 자산 | 없음 ⚠️ |
| 새로 만들 것 | **종목명 → 종목코드 조회 계층, 동일·유사 종목명 모호성 처리** |
| 이벤트 | `stock_resolved`, `stock_resolution_failed`, `stock_ambiguous` |
| 테스트 | `삼성전자` 정상 변환, `삼성전자우` 구분, 존재하지 않는 종목명, 오타 |

> ⚠️ **기존 n8n 워크플로우에 이 계층이 없습니다.** 시세조회·주문 서브워크플로우는 종목코드를 입력으로 받을 것으로 보이지만, 사용자는 자연어로 종목명을 말합니다. **이 변환 계층은 신규 작업입니다.**

### 3.3 판단 근거

| 연결 대상 | 필요한 내용 |
|---|---|
| 데이터 | 근거ID, 주문번호, 선택한 근거 유형, 추가 메모, 입력시각 |
| 대화 | 주문 확인 후 근거 선택지 제시 → 선택 → 추가 메모(선택) |
| 기존 자산 | 데이터 저장소 ✅ |
| 새로 만들 것 | 근거 유형 선택지 설계, 근거-주문 연결, 저장 스키마 |
| 이벤트 | `rationale_recorded`, `rationale_skipped` |
| 테스트 | 선택만 입력, 선택+메모 입력, 근거 입력 없이 이탈 |

## 4. 이 프로젝트에서 다루지 않는 도메인 요소

교안 4.3에 따라 처음부터 모든 요소를 만들지 않습니다.

| 요소 | 제외 이유 |
|---|---|
| 실전 계좌 | 실제 자금 위험. 프로젝트 목적과 무관 |
| 종목 추천 결과 | 특정 종목 매수 권유는 유사투자자문 영역 |
| 수익률 예측 | 검증 불가하고 목적과 무관 |
| 차트·기술적 지표 자동 분석 | 5일 일정에 들어가지 않음 |
| 뉴스·공시 | 외부 데이터 수집 범위가 큼 |
| 다중 사용자·권한 체계 | 이번 프로젝트는 본인 단일 사용자 |
| 백테스팅 | 별도 프로젝트 규모 |
