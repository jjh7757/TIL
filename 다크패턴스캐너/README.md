# 다크패턴 스캐너 — 쇼핑몰 다크패턴 자동 진단 프로토타입

> **상태: 보류 (2026-08-17)** — 실사이트 4곳 검증 결과 전부 다크패턴 미발견. 탐지기 자체는
> 유효하지만, 이 스캔에 셀러가 돈을 낼지에 대한 수요 검증 없이는 재개하지 않기로 함.
> 보류 사유·재개 조건은 [기획서.md](기획서.md) 9장 참고.

쇼핑몰 셀러가 자기 스토어를 스캔하면 법적으로 문제 될 수 있는 다크패턴(가짜 긴급성,
숨은 갱신, 취소 방해, 숨은 비용 등)을 자동으로 찾아 리포트해주는 셀프서브 컴플라이언스
아이디어의 프로토타입. 자세한 배경·경쟁 조사·수익화 검토는 [기획서.md](기획서.md) 참고.

## 핵심 차별점

경쟁 제품(Shopify StoreHQ, 카페24 Sentio5)은 둘 다 **관리자 API로 설정값만** 점검하고
스토어프론트를 보지 않는다 (두 시장에서 독립적으로 확인). 이 프로토타입은 **Playwright로
실제 화면을 렌더링하고 상호작용**해서 검증한다.

## 무엇을 만들었나

- [`scanner/countdown.py`](scanner/countdown.py) — 카운트다운 리셋 탐지.
  같은 페이지를 A(첫 방문) → B(같은 브라우저에서 새로고침) → C(저장소가 빈 새 브라우저
  컨텍스트로 재방문) 세 조건으로 열어, 남은 시간이 벽시계 위 하나의 마감으로 수렴하는지
  판정한다. `fake_session`(새로고침마다 리셋) / `fake_storage`(쿠키 지우면 리셋) /
  `genuine`(정상) 세 가지로 구분하고, "재고 N개 남음" 류 수량 주장도 세션 간 변동
  여부로 함께 검증한다.
- [`scanner/checkout.py`](scanner/checkout.py) — 체크아웃 총액 추적.
  결제 단계를 실제로 클릭해 이동하며 각 화면의 총액을 파싱한다. 신규 비용 항목뿐
  아니라 "무료배송"이라 광고해놓고 결제 단계에서 배송비를 청구하는 것처럼 **같은
  항목명의 금액이 나중에 오르는** 경우도 구분해서 잡는다. 사전 선택된 유료
  옵션(체크박스/라디오/셀렉트)도 함께 탐지한다.
- [`scanner/timeparse.py`](scanner/timeparse.py), [`scanner/money.py`](scanner/money.py),
  [`scanner/dom.py`](scanner/dom.py) — 콜론·단위 표기가 섞인 남은시간 파싱, 화면
  텍스트에서 금액·항목명 추출, 재로드 후에도 같은 요소를 다시 찾을 CSS 경로 생성 등
  탐지의 기반이 되는 유틸리티. 실사이트 검증 중 발견한 것들도 반영됨: 마퀴 배너의
  반복 문구 중복 제거, open shadow DOM 안에 렌더링되는 서드파티 위젯(리뷰·추천 팝업 등)
  까지 순회하는 탐색.
- [`scanner/checkout.py`](scanner/checkout.py)의 `Step` — 실제 결제 흐름은 `goto`/`click`만으로
  부족한 경우가 많아 두 가지를 추가함: 필수 옵션(색상 등)을 먼저 골라야 하는 상품용 `select`,
  Playwright의 가시성 검사에 걸려 타임아웃 나는 버튼을 위한 `js_click`(DOM에 직접 클릭 이벤트
  디스패치).
- [`scanner/report.py`](scanner/report.py) — 탐지 결과를 심각도·위치·법적 근거(전자상거래법
  다크패턴 6개 유형 매핑)·조치 방법으로 정리한 리포트.

## 정답을 아는 fixture로 자체 검증

`fixtures/`에 정답을 미리 아는 대조군을 직접 만들어 탐지기가 그 정답을 맞히는지 확인했다.

| fixture | 정답 | 판정 근거 |
|---|---|---|
| `fake_urgency.html` | 가짜 긴급성 | 새로고침만 해도 초기화 |
| `cookie_urgency.html` | 가짜 긴급성 | 같은 브라우저에선 이어지지만 새 방문자는 초기화 |
| `real_deadline.html` | 정상 | 벽시계 기준 고정 마감 |
| `checkout/step1~3` | 숨은 비용 | 배송비·수수료·포장비가 결제 단계에서 처음 등장 |
| `checkout/ghost_step1~3` | 숨은 비용(유령 배송비) | "무료배송" 광고 후 배송비 0원→3,000원 |
| `checkout/honest_step1~3` | 정상 | 1단계부터 총액 고지, 끝까지 유지 |

`python run_scan.py demo` 실행 결과 **8/8 판정 일치, 오탐 0건**.

개발 중 실제로 오탐 3건을 발견하고 고쳤다: 타이머 문구("00:09:58 남음")가 재고
표시로 오인된 것, 상품 페이지의 원가가 장바구니 단계의 "신규 비용"으로 오인된 것,
같은 라벨의 금액 인상(무료배송 → 유료 배송비)을 놓치던 것.

## 사용법

```bash
pip install playwright
playwright install chromium

python run_scan.py demo                 # fixture로 탐지기 자체 검증
python run_scan.py timer <url>          # 카운트다운·재고 표시 검사
python run_scan.py checkout <flow.json> # 결제 흐름을 따라가며 총액 추적
```

## 실사이트 검증 — 4연속 클린, 그래서 보류

fixture 다음 단계로 실제 쇼핑몰 4곳에 돌렸다.

| 대상 | 검사 | 결과 |
|---|---|---|
| 무신사 (대형 마켓플레이스) | 홈 배너 카운트다운 | `genuine` — 실제 마감 기반 정상 |
| 오롤리데이 (카페24, 카페24 "우수 고객사" 쇼케이스) | 체크아웃 총액 추적 | 증가 없음, 정상 |
| 쿤달 (카페24, 같은 쇼케이스) | 체크아웃 총액 추적 | 25,500원 → 25,500원, 3연속 재현, 정상 |
| 오롤리데이 재검사 | "98명이 보고 있는 상품" 위젯(서드파티 앱) | `stable` — 다크패턴 미확정 |

과정에서 실제 버그 4개를 찾아 고쳤다 — 회전 배너(캐러셀)가 다른 슬라이드 문구를 타이머로
오인, 캐러셀 페이드 타이밍 때문에 진짜 타이머를 후보에서 놓침, `select` 직후 곧바로
클릭하면 서버는 200을 반환해도 실제로는 담기지 않는 경합, 서드파티 위젯이 open shadow DOM
안에 있어 아예 안 보이던 것. 탐지기 신뢰도는 세션 초반보다 훨씬 올라갔지만 결과는 계속 클린.

표본이 "다크패턴이 없을 법한 곳"(대기업·카페24 쇼케이스 브랜드)에 편중된 한계는 있으나,
사이트를 한 곳씩 더 스캔하는 방식으로는 진짜 질문("셀러가 이 스캔에 돈을 낼 것인가")에
답이 안 나온다고 판단해 보류. 자세한 보류 사유·재개 조건은 [기획서.md](기획서.md) 9장 참고.
