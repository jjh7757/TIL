# 다크패턴 자동 진단 앱 — 프로젝트 기획서

> 최종 업데이트: 2026-08-16
> 상태: **프로토타입 1차 완성 — 카운트다운 리셋 탐지·숨은 비용 추적 실증 완료**

---

## 1. 한 줄 정의

쇼핑몰 셀러가 앱스토어에서 설치해 자기 스토어를 스캔하면, 법적으로 문제 될 수 있는
**다크패턴(가짜 긴급성, 숨은 갱신, 취소 방해, 숨은 비용 등)을 자동으로 찾아 리포트**해주는
셀프서브 컴플라이언스 앱.

**핵심 차별점: 관리자 설정값이 아니라 실제 렌더링된 화면과 결제 흐름을 검사한다.**

## 2. 왜 이 아이디어인가 — 검증 경로

### 2-1. 시장 근거
- 2024.2 개정 전자상거래법 통과 → **2025.2 시행**, 다크패턴 6개 유형 명문 금지
- **2025.10.15 공정위 첫 과태료 부과** (OTT·음원·커머스 구독 플랫폼 4개사)
  → 법이 종이호랑이가 아님이 증명됨
- 제재: 시정조치 + 500만원 이하 과태료. 반복 시 영업정지 3→6→12개월로 확대

### 2-2. 법정 6개 유형 (전자상거래법)
1. 숨은 갱신
2. 순차공개 가격책정 (숨은 비용)
3. 특정 옵션 사전 선택
4. 잘못된 계층구조
5. 취소·탈퇴 방해
6. 반복 간섭

### 2-3. 유통 채널 — "1인 개발자가 혼자 팔 수 있는가"가 관건이었음
초기엔 국내 이커머스(쿠팡·11번가 등 오픈마켓) 대상으로 구상했으나,
**오픈마켓은 엔터프라이즈 영업이 필요해 1인 개발자에게 부적합**하다고 판단.
→ 쇼핑몰 솔루션 앱스토어(셀프서브)로 방향 전환

| | 카페24 앱스토어 | Shopify 앱스토어 |
|---|---|---|
| 개발자센터 | developers.cafe24.com | 있음 |
| 수익 배분 | **개발자 80% / 카페24 20%** (카드·PG 수수료 포함) | 연 $1M까지 0%, 이후 15% |
| 판매 | 심사 후 즉시, 셀프서브 | 동일 |
| 개발 환경 | **웹앱 — OS 무관, 윈도우 가능** | 동일 |

※ 아임웹도 앱스토어·개발자센터 보유
※ **Shopify 앱 = 웹앱**. iOS 앱이 아니므로 macOS·Xcode 불필요. 현재 스택(FastAPI+Docker) 그대로 사용 가능

## 3. 경쟁 조사 결과 ★핵심★

  (SEO & AEO Audit 6, AI Alt Text 3, Compliance Scanner 0, AI Readiness Audit 0)
  → 감사 앱을 여러 개 뿌려보는 초기 인디 팀. 유료화한 앱은 Alt Text 하나뿐

  and **hidden fees**" / "Checks **auto-renewal**, **cancellation**, renewal-term disclosure"

**실제 스캔 테스트 결과 (2026.8.16, 신규 체험 스토어에서 실행):**

- Policies & Cookies:  17점, 13 issues (17/18 checked)

발견 항목의 Where가 전부 `Settings → Policies`, `Settings → Customer privacy` 등

## 4. 제품 설계

### 4-1. 핵심 기술 — 이것이 차별점
기존 도구가 못 하는 것 = **실제 렌더링·상호작용 검증**

| 다크패턴 | 탐지 방법 |
|---|---|
| 가짜 긴급성 (카운트다운) | 페이지를 **두 번 로드해 타이머가 리셋되는지 비교** |
| 가짜 재고 부족 | 재고 표시가 시간·세션에 따라 변하는지 관찰 |
| 숨은 비용 | **체크아웃을 끝까지 진행**하며 단계별 총액 변화 추적 |
| 사전 선택 옵션 | DOM에서 기본 checked 상태 검사 |
| 취소·탈퇴 방해 | 해지 경로까지의 클릭 depth 측정 |
| 잘못된 계층구조 | 버튼 크기·색상 대비로 시각적 우열 분석 |

스택: **Playwright(헤드리스 렌더링) + DOM/텍스트 분석 + LLM 분류**
→ 규칙으로 잡히는 건 규칙으로, 문구 뉘앙스 판단만 LLM (비용 통제)

### 4-2. 기술 리스크 낮음 — 선행 연구 재사용 가능
- **UIGuard** (학계) — 정상 UI 4,999개 + 다크패턴 UI 1,353개 데이터셋
- **AppRay** (학계) — LLM으로 앱 탐색하며 다크패턴 탐지
- **Dark Pattern Detector** — 크롬 확장, TinyBERT 기반 (배포됨)
- **WebGuard, DarkPatternLLM** — 오픈소스
→ 탐지 기법 자체는 이미 여러 번 검증됨. 우리가 할 일은 **로컬라이제이션 + 렌더링 검증 + 제품화**

### 4-3. 산출물
심각도 순위 리포트 + 위치 + **한국 전자상거래법 조항 매핑** + 수정 가이드 + 정기 재스캔

## 6. 다음 할 일

### 6-1. [완료 2026-08-16] 프로토타입으로 기술 우위 증명
`C:\Users\user\Downloads\부트캠프\darkpattern-scanner\` 에 구현 완료.

- **카운트다운 리셋 탐지** (`scanner/countdown.py`): 같은 페이지를 A(첫 방문) →
  B(같은 컨텍스트 새로고침) → C(저장소 빈 새 컨텍스트 재방문) 세 조건으로 열어
  남은 시간이 벽시계 기준 하나의 마감으로 수렴하는지 판정.
  `fake_session`(새로고침마다 리셋) / `fake_storage`(쿠키 지우면 리셋) / `genuine`
  세 가지로 구분. 재고·조회수 같은 "몇 명이 보는 중" 류 숫자도 세션 간 변동 여부로 검증.
- **체크아웃 총액 추적** (`scanner/checkout.py`): 단계를 실제로 클릭해 이동하며
  각 화면의 총액을 파싱, 어느 단계에서 얼마가 왜 늘었는지(신규 항목 vs. 같은 라벨의
  금액 인상 — 예: "무료배송"인데 결제 단계에서 배송비 청구) 를 구분해서 리포트.
  사전 선택된 유료 옵션(체크박스/라디오/셀렉트)도 함께 탐지.
- **정답을 아는 fixture 로 자체 검증**: `fixtures/` 에 가짜 타이머 3종 + 정상 대조군,
  결제 흐름 3종(숨은 비용/유령 배송비/정상)을 직접 만들어 `python run_scan.py demo` 로
  8/8 판정 일치 확인. 오탐 없이 정상 흐름은 "탐지된 항목 없음"으로 통과.
- 실행: `python run_scan.py demo` (fixture 검증) / `timer <url>` / `checkout <flow.json>`
- **다음 단계**: 실제 쇼핑몰(가능하면 Shopify 체험 스토어)에 대고 돌려서 진짜 사이트의
  DOM 다양성에도 선택자·파서가 버티는지 확인. `#timer` 처럼 id 가 있는 fixture와 달리
  실제 사이트는 프레임워크 클래스명이 뒤섞여 있어 `innermostMatches` 휴리스틱이 얼마나
  버티는지가 관건.

**메타 교훈**
1. 2026년 시점에 "공개 데이터 + AI"로 몇 초 만에 떠올릴 수 있는 아이디어는 대부분 이미 있음
2. 경쟁자 조사는 **우리가 쓸 용어가 아니라 그 제품이 실제로 하는 일**로 검색해야 함
3. 잘 만든 제품이 있는데도 아무도 안 쓰면 → 경쟁 문제가 아니라 **수요 문제**
4. 기술이 되는 것보다 **1인이 팔 수 있는 유통 경로가 있는지**가 더 큰 제약이었음
