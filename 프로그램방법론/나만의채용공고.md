## 기술 스택

### 1) 현재 충족하는 사항
- Python 기초 문법·표준 모듈 ([파이썬 기초](../CS지식/파이썬기초/README.md))
- REST API 연동 — requests, HTTP 메서드/상태코드 ([requests실습](../CS지식/requests실습.md))
- n8n 워크플로우 자동화 (VOC 분석·금융뉴스브리핑·금융투자봇 등 다수 프로젝트)
- LLM API 직접 연동 — Claude, Gemini
- Docker 배포 (셀프호스팅, Compose, 리버스 프록시·HTTPS까지 실전 경험)
- Next.js/Vercel + Supabase 웹 서비스 구현 (왜샀어, 맛집추천서비스)
- Git/GitHub

### 2) 단기간에 충족 가능한 사항
- LangChain/LangGraph — 이미 LLM API 직접 호출·n8n 오케스트레이션 경험이 있어 프레임워크 문법만 익히면 진입 가능
- Function Calling/Tool Use 구현 — Claude/Gemini API를 이미 다뤄봤으니 스펙 학습 위주
- MCP(Model Context Protocol) — Claude 생태계를 이미 쓰고 있어 진입 장벽 낮음
- 비동기 처리(asyncio) — Python 기초는 있으니 심화만 필요
- SQL 심화 — Supabase 테이블 설계 경험을 정형 RDB 쿼리로 확장

### 3) 장기간이 필요한 사항
- Kubernetes, AWS ECS 등 컨테이너 오케스트레이션 (원티드랩) — 단일 서버 Docker 배포와는 다른 차원의 운영 경험 필요
- VectorDB 기반 RAG 프로덕션 운영 — 임베딩·검색 품질 튜닝은 실사용 데이터로 반복해야 느는 영역 (넥스트증권, 피피에스)
- 대규모 트래픽 대응 아키텍처 — 캐싱, 모델 서빙 인프라(gRPC 등), 비동기 파이프라인 (원티드랩)
- NestJS 등 정형 백엔드 프레임워크 실무 경험 (모비니티) — 지금은 Next.js API route 수준

## 자격 요건

### 1) 현재 충족하는 사항
- Python 기본 프로그래밍 역량
- Git 버전 관리 사용 경험
- "AI Agent 플랫폼(Claude, n8n) 이해" — 스케일아키텍처 공고 요건과 거의 정확히 일치
- 다수 외부 API 연동 경험 (KIS, 네이버, Gemini)
- 클라우드 서버 배포 경험 (네이버클라우드 Docker 셀프호스팅, 도메인·HTTPS 연결)

### 2) 단기간에 충족 가능한 사항
- RESTful API "설계" 경험 명문화 — 지금까진 대부분 소비자 입장에서 API를 호출만 했으니, 직접 엔드포인트를 설계한 프로젝트를 하나 만들면 충족
- RDB/NoSQL 이해도 심화 — Supabase 경험을 정식 SQL/NoSQL 비교 학습으로 확장
- AWS 클라우드 환경 경험 — 네이버클라우드 경험이 있으니 AWS로 전이 학습 가능

### 3) 장기간이 필요한 사항
- 5년 이상 소프트웨어 엔지니어링 경력 (원티드랩, 넥스트증권) — 시간이 곧 요건이라 단기 학습으로 대체 불가
- 프로덕션 환경에서 실사용자 트래픽 기준으로 LLM 에이전트 시스템을 구축·배포한 경험
- 비동기 처리·캐싱·로깅·모니터링을 실운영 규모에서 다뤄본 서비스 안정성 확보 경험

## 우대 사항

### 1) 현재 충족하는 사항
- API 연동 및 자동화 워크플로우 구축 경험 (n8n 다수 프로젝트)

### 2) 단기간에 충족 가능한 사항
- MCP 프로토콜 경험
- 특정 도메인(금융 등) 이해 — 이미 KIS 모의투자 API 연동 경험 있음

### 3) 장기간이 필요한 사항
- 멀티 에이전트 프레임워크 실전 경험 — LangChain, LangGraph, AutoGen 등을 개인 프로젝트가 아니라 실제 트래픽이 있는 프로덕션에서 운영해본 경험 (넥스트증권)
- RAG 파이프라인 + VectorDB 프로덕션 운영 — 구축 자체는 단기간에 흉내낼 수 있지만, 실서비스 검색 품질을 튜닝하며 운영한 경험은 시간이 필요 (넥스트증권, 피피에스)
- 정교한 Function Calling / Tool Use 에이전트 제어 — 여러 실패 케이스를 겪으며 에이전트 행동을 통제하는 노하우 (넥스트증권)
- 대규모 컨테이너 오케스트레이션 운영 — Docker 단일 서버 배포를 넘어 Kubernetes, AWS ECS 등으로 다중 서비스를 실제 운영해본 경험 (원티드랩)
- AI 기능의 성능·비용·지연시간 최적화 — 트래픽이 실제로 있어야 측정하고 개선할 수 있는 항목이라 시간 자체가 필요 (원티드랩)
- 5년 이상 소프트웨어 엔지니어링 경력 자체 — 여러 프로젝트를 거치며 쌓이는 트러블슈팅 총량이 요건이라 단기 학습으로 대체 불가 (원티드랩, 넥스트증권)

## 종합 전략

세 카테고리의 "3) 장기간 필요" 항목은 결국 같은 축 — **실사용자 트래픽이 있는 프로덕션 운영 경험의 총량**으로 수렴한다. 지금 단계에서는 왜샀어·자동화봇 같은 개인 프로젝트를 계속 운영 상태로 유지하면서, 소규모라도 실사용자 피드백·장애 대응 이력을 쌓아 이 항목들의 축소판 실적을 미리 만들어두는 것이 가장 현실적인 전략이다.
