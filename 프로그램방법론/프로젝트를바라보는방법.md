# 프로젝트, 프로덕트, 운영 구분하기
## 프로젝트란
-특정 문제를 해결하기 위해 일정 기간 동안 수행하여 고유한 결과물을 만드는 활동

-예시
``` text
6주 동안 AI 메뉴 추천 MVP를 만들어
테스트 사용자의 메뉴 선택 시간을 평균 5분에서 3분 이하로 줄입니다
```

## 프로덕트란
-특정 사용자의 문제를 반복적으로 해결하며 지속적으로 가치를 제공하는 제품이
나 서비스

-ex) 배달앱

## 운영이란
-프로덕트가 배포된 후에도 안정적으로 가치를 제공하도록 유지하는 반복 업무

-예시
``` text
서버 장애 확인
결제 오류 대응
고객 문의 처리
추천 품질 점검
비용과 성능 확인
```

## 정리
-프로젝트는 특정 문제를 해결하기 위한 결과물을 만드는 활동이고,
프로덕트는 프로젝트를 통해 만든 제품이나 서비스이며,
운영은 프로덕트가 잘 작동하도록 유지보수하는 업무이다.

# 문제에서 프로젝트를 시작하는 방법
## 좋은 프로젝트 문장의 작성 구조
``` text
[사용자]가 [상황]에서 겪는 [문제]를
[해결 방식]으로 줄여
[확인 가능한 변화]를 만듭니다.
```
## 예시
``` text
혼자 점심을 주문하는 직장인이 메뉴가 많아 선택에 오래 걸리는 문제를
예산, 거리, 선호 음식 기반 추천으로 줄여
3분 안에 주문 후보를 선택할 수 있도록 합니다.
```

## 기준선이란
-프로젝트를 시작할 때 팀이 합의한 목적, 용어, 데이터, 흐름, 산
출물, 완료 조건을 기록한 기준 문서

### 기준선이 필요한 이유
``` text
프로젝트 목표가 고정됩니다.
팀원들이 같은 용어를 사용합니다.
도메인 요소와 기능의 관계가 보입니다.
데이터가 어디에서 발생하고 이동하는지 확인할 수 있습니다.
기능 구현 순서가 명확해집니다.
테이블, API, 클래스, 함수 이름을 일관되게 작성할 수 있습니다.
브랜치와 산출물 기준이 정리됩니다.
완료 여부를 다른 팀원이 확인할 수 있습니다.
```

### 기준선 필수 항목
``` text
1. 프로젝트 목적
2. 문제 정의
3. 도메인 정의
4. 사용자 역할
5. 업무 흐름
6. 데이터 소스
7. 데이터 유형
8. 도메인 이벤트
9. 데이터 흐름
10. 용어와 네이밍 컨벤션
11. 산출물 기준
12. 완료 체크리스트
```
