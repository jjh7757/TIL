# 0단계 — 계정과 가드레일 설정

[배포 환경 구축 계획](README.md)의 0단계 상세 절차.

루트 계정은 계정의 모든 권한을 가지며 **권한을 제한할 수단이 없다.** 탈취되면 복구가 불가능하고,
청구서를 막을 방법도 없다. 그래서 루트는 MFA로 잠그고, 일상 작업은 권한을 제한할 수 있는
IAM 사용자로 한다.

## 1. 루트 계정 MFA

콘솔 우측 상단 계정 이름 → **Security credentials**
→ Multi-factor authentication (MFA) → **Assign MFA device**

AWS는 현재 독립 계정의 루트 사용자에게 MFA를 필수로 요구하므로, 로그인 시 자동으로 안내될 수도 있다.

### 어떤 방식을 고를까

| 방식 | 평가 |
|---|---|
| **Passkey / 보안 키** | 윈도우 Hello를 패스키로 쓸 수 있다. 피싱에 강하고 가장 편함 |
| **Authenticator 앱 (TOTP)** | 가장 일반적. 백업되는 앱을 쓸 것 |
| 하드웨어 TOTP 토큰 | 별도 구매 필요 |

Authenticator 앱을 쓴다면 **백업·동기화가 되는 앱**을 고른다(Authy, 1Password,
Microsoft Authenticator 등). 백업 없는 앱에 등록했다가 폰을 잃으면 루트 접근이 막히고,
복구는 이메일·전화 본인확인을 거치는 느린 절차가 된다.

### MFA 기기는 2개 등록한다

루트 사용자는 MFA 기기를 최대 8개까지 등록할 수 있다. **반드시 2개 이상 등록할 것.**
하나가 날아가도 다른 하나로 들어갈 수 있다. 예: 폰 Authenticator 앱 + 노트북 패스키.

TOTP 등록 화면의 "Show secret key"로 나오는 시크릿을 비밀번호 관리자에 따로 보관해두면
나중에 다른 기기에 같은 코드를 재등록할 수 있다.

## 2. IAM 사용자와 로그인 URL에 필요한 계정 별칭

IAM → Account settings 쪽의 **Account Alias**를 설정하면 로그인 URL이 짧아진다.

```
https://<별칭>.signin.aws.amazon.com/console
```

설정하지 않으면 12자리 계정 ID를 외워야 한다.

## 3. 관리자 그룹 만들기

사용자에 정책을 직접 붙이는 대신 그룹에 붙인다. 나중에 사용자가 늘어도 권한을 한 곳에서 관리한다.

IAM → **User groups** → Create group

- 이름: `Administrators`
- 권한 정책: `AdministratorAccess` 연결

## 4. IAM 관리자 사용자 만들기

IAM → **Users** → Create user

1. 사용자 이름 (예: `jjh-admin`)
2. **"Provide user access to the AWS Management Console"** 체크
   → "I want to create an IAM user" 선택 → 비밀번호 설정
3. 권한: **Add user to group** → `Administrators` 선택
4. 생성 후 나오는 **로그인 URL을 저장**해 둔다

## 5. IAM 사용자에게도 MFA를 건다

만든 사용자 → Security credentials 탭 → MFA → Assign MFA device

관리자 권한을 가진 사용자이므로 루트와 똑같이 보호해야 한다. 여기서 빠뜨리기 쉽다.

## 6. 청구 정보 접근 활성화 — 놓치기 쉬운 함정

**`AdministratorAccess`를 붙여도 IAM 사용자는 기본적으로 Billing 콘솔을 볼 수 없다.**
루트 계정에서 한 번 켜줘야 한다.

**루트로 로그인** → 계정 이름 → **Account** → "IAM user and role access to billing information"
→ **Edit** → Activate → Update

이걸 안 켜면 다음 단계인 Budgets 예산 알람을 IAM 사용자로 만들 수 없다.

## 7. 이후 루트 계정은 쓰지 않는다

로그아웃하고 IAM 사용자로 다시 로그인해서 이후 작업을 진행한다.
루트가 필요한 일은 정해져 있다.

- 계정 플랜 변경(Free → Paid), 결제 수단 변경
- 계정 해지
- 위 6번 같은 계정 수준 설정
- IAM 사용자로 풀 수 없는 지원 케이스

## 8. 로컬 CLI용 액세스 키 (필요할 때만)

`aws ssm start-session`으로 서버에 붙는 등 로컬에서 CLI를 쓰려면 액세스 키가 필요하다.

IAM → 사용자 → Security credentials → **Create access key** → "Command Line Interface (CLI)"

```bash
aws configure
```

**이 키가 이 구성에서 유일한 장기 자격증명이다.** 배포 파이프라인은 OIDC로 임시 자격증명을
쓰기 때문에 GitHub에는 키를 넣지 않는다. 로컬 키도 다음을 지킨다.

- 저장소에 절대 커밋하지 않는다 (`~/.aws/credentials`에만 둔다)
- 안 쓰게 되면 바로 비활성화·삭제한다
- 유출이 의심되면 즉시 삭제하고 새로 만든다

당장 필요 없으면 만들지 않고 넘어가도 된다.

## 9. Budgets 예산 알람

IAM 사용자로 로그인한 상태에서 Billing and Cost Management → **Budgets** → Create budget

**템플릿 – 월별 비용 예산**을 그대로 쓴다. 기본 알림이 실제 85% / 실제 100% / **예측 100%**
세 가지라 따로 커스터마이즈할 필요가 없다.

- 예산 이름: `monthly-cost-guard`
- 예산 금액: **$10**
- 이메일 수신자: 가입 이메일

**금액을 낮게 잡는 게 요점이다.** 예상 비용이 연말까지 월 $3이므로, $10으로 두면 85% 알림이
$8.50에서 울린다. 예상의 3배 수준이라 이상 징후를 조기에 잡는 지점이다.
$100 같은 큰 금액으로 두면 첫 알림이 올 때쯤엔 이미 한 달을 잘못 태운 뒤다.

**예측(Forecasted) 100% 알림**이 특히 중요하다. NAT Gateway(월 $35)를 실수로 켜도
실제 청구액이 쌓이기 전에 추세로 먼저 경고가 온다.

> **2027년 1월에 예산을 $30으로 올릴 것.** t4g 무료 트라이얼이 끝나 정상 비용이 월 $18이
> 되면 $10 예산은 매달 울린다.
