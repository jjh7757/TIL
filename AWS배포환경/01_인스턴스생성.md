# 1단계 — 네트워크와 인스턴스

[배포 환경 구축 계획](README.md)의 1단계 상세 절차.
**시작 전 우측 상단 리전이 "아시아 태평양(서울)"인지 확인한다.**

순서가 중요하다. IAM 역할을 먼저 만들어야 인스턴스 생성 화면에서 바로 붙일 수 있다.

## 1. IAM 역할 (인스턴스 프로파일)

IAM → **Roles** → Create role

1. 신뢰할 수 있는 엔터티 유형: **AWS 서비스**
2. 사용 사례: **EC2**
3. 권한 정책: **`AmazonSSMManagedInstanceCore`** 검색해서 체크
4. 역할 이름: **`ec2-deploy-target`**
5. 생성

생성 후 이 역할에 인라인 정책을 하나 더 추가한다.

역할 → Permissions → Add permissions → **Create inline policy** → JSON 탭
→ [`templates/iam/ec2-instance-profile-permissions.json`](templates/iam/ec2-instance-profile-permissions.json) 내용 붙여넣기
→ 이름 `ecr-pull` 로 저장

`AmazonSSMManagedInstanceCore`는 SSM 접속에, 인라인 정책은 ECR에서 이미지를 받아오는 데 쓴다.
서버는 이미지를 **받기만** 하므로 푸시 권한은 주지 않는다.

## 2. 키 페어 — 안전망으로만

SSM으로 접속할 것이므로 평소에 SSH는 쓰지 않는다. 하지만 **SSM 에이전트나 IAM 설정이
잘못되면 서버에 들어갈 수단이 아예 없어진다.** 왜샀어 때 sshd가 죽어 콘솔로 겨우 복구했던
것과 같은 상황이 될 수 있다.

그래서 **키 페어는 붙여두되 보안 그룹에서 22번 포트를 열지 않는다.**
평소에는 포트가 닫혀 있어 공격 표면이 없고, SSM이 고장 나면 보안 그룹에 내 IP만
임시로 허용해서 들어갈 수 있다.

기존 키를 재사용한다. 로컬에서 공개키를 확인한다.

```bash
cat ~/.ssh/aws_deploy.pub
```

EC2 → **Key Pairs** → **Actions** → **Import key pair**

- 이름: `deploy-key`
- 위 공개키 문자열 붙여넣기

## 3. 보안 그룹

EC2 → **Security Groups** → Create security group

- 이름: `web-server-sg`
- 설명: `HTTP/HTTPS only, SSH closed (SSM access)`
- VPC: 기본 VPC

**인바운드 규칙**

| 유형 | 포트 | 소스 |
|---|---|---|
| HTTP | 80 | `0.0.0.0/0` |
| HTTP | 80 | `::/0` |
| HTTPS | 443 | `0.0.0.0/0` |
| HTTPS | 443 | `::/0` |

**SSH(22)는 추가하지 않는다.**

**아웃바운드 규칙**은 기본값(전체 허용) 그대로 둔다. SSM 에이전트가 AWS 엔드포인트로
443 아웃바운드를 열어야 접속이 성립한다. 여기를 막으면 SSM이 붙지 않는다.

## 4. 인스턴스 시작

EC2 → **Instances** → **Launch instances**

| 항목 | 값 | 주의 |
|---|---|---|
| 이름 | `deploy-server` | |
| AMI | **Ubuntu Server 24.04 LTS** | |
| 아키텍처 | **64비트(Arm)** | **x86을 고르면 t4g를 선택할 수 없다** |
| 인스턴스 유형 | **`t4g.small`** | "프리 티어 사용 가능" 표시 확인 |
| 키 페어 | `deploy-key` | |
| VPC | 기본 VPC | |
| 서브넷 | 기본값 (퍼블릭) | |
| **퍼블릭 IP 자동 할당** | **활성화** | 끄면 인터넷에 못 나가 SSM이 안 붙는다 |
| 보안 그룹 | 기존 선택 → `web-server-sg` | |
| 스토리지 | **gp3 30GB** | 기본 8GB에서 반드시 올릴 것 |
| 고급 세부 정보 → **IAM 인스턴스 프로파일** | **`ec2-deploy-target`** | 여기를 빠뜨리면 SSM도 ECR도 안 된다 |

NAT Gateway는 만들지 않는다. 퍼블릭 서브넷 + 인터넷 게이트웨이면 충분하다.

## 5. Elastic IP

기본 퍼블릭 IP는 인스턴스를 중지·시작하면 바뀐다. 도메인을 붙일 것이므로 고정 IP가 필요하다.

EC2 → **Elastic IPs** → **Elastic IP 주소 할당** → 할당
→ 해당 IP 선택 → **작업** → **Elastic IP 주소 연결** → 인스턴스 `deploy-server` 선택 → 연결

**연결된 상태에서는 무료지만, 할당만 해두고 어디에도 안 붙이면 과금된다.**
인스턴스를 종료할 때는 Elastic IP도 같이 릴리스할 것.

## 6. 확인

인스턴스가 `running`이 되고 2~5분 뒤 SSM에 등록된다. 바로 안 잡혀도 조금 기다린다.

**콘솔에서**: Systems Manager → **Fleet Manager** 에 인스턴스가 보이면 성공.

**접속 테스트**: EC2 → 인스턴스 선택 → **연결** → **Session Manager** 탭 → 연결

붙으면 다음을 확인한다.

```bash
uname -m          # aarch64 여야 한다
free -h           # 약 2GB
df -h /           # 약 30GB
aws sts get-caller-identity   # 역할이 붙었는지 (AWS CLI는 2단계에서 설치)
```

### SSM에 안 잡힐 때

1. IAM 인스턴스 프로파일이 붙어 있는가 (가장 흔한 원인)
2. 퍼블릭 IP가 할당돼 있는가
3. 보안 그룹 **아웃바운드**가 열려 있는가
4. 서브넷의 라우팅 테이블이 인터넷 게이트웨이로 향하는가

인스턴스 생성 후에 IAM 프로파일을 붙였다면 재부팅해야 에이전트가 자격증명을 다시 읽는다.
