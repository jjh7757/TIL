# AWS 배포 환경 구축 계획

만든 걸 바로 올릴 수 있는 상시 배포 서버를 AWS 단일 벤더로 구성한다.
실제 구축 과정과 트러블슈팅은 [구축기록.md](구축기록.md)에,
이 환경에 앱을 처음 올린 기록은 [rag앱배포기록.md](rag앱배포기록.md)에,
리소스 식별자는 [환경정보.md](환경정보.md)에 모아둔다.

관련: [컨테이너 기반 배포 기초](../CS지식/컨테이너배포기초.md), [왜샀어 Docker 배포 전환](../vercel실습/왜샀어/Docker배포전환.md)

## 왜 AWS 단일 구성인가

- 취업 스펙으로 AWS를 쓰려는 게 애초 동기였다. 서버를 다른 벤더에 두면 그 동기가 반만 충족된다.
- 벤더를 하나로 줄이면 계정·과금·권한이 한 곳에 모여 관리 비용이 준다.
- EC2를 쓰면 VPC / 서브넷 / 보안 그룹 / IAM / EBS를 실제로 만지게 된다. 면접에서 물어보는 게 정확히 이 부분이고, Lightsail은 이걸 전부 감춘다.

기존 네이버클라우드 서버(왜샀어)는 2027년 8월까지 무료이므로 그때까지 그대로 둔다.
무료가 끝나는 시점에 이 AWS 서버로 합칠지 결정한다. 미리 옮길 이유는 없다.

## 결정 사항

| 항목 | 선택 | 이유 |
|---|---|---|
| 리전 | `ap-northeast-2` (서울) | 지연시간. 왜샀어를 나중에 합칠 때도 유리 |
| 인스턴스 | `t4g.small` (2 vCPU / 2GB, Graviton2 ARM) | **2026-12-31까지 월 750시간 무료** |
| OS | Ubuntu 24.04 LTS **arm64** | 기존 서버와 동일해서 경험이 그대로 이어짐 |
| 디스크 | EBS gp3 30GB | 왜샀어 때 디스크 풀을 겪었으므로 기본값보다 넉넉히 |
| 이미지 저장소 | ECR | GHCR 대신. AWS 단일 구성 + 이력서 키워드 |
| 빌드 위치 | GitHub Actions | **서버에서 절대 빌드하지 않는다** (아래 참조) |
| 배포 경로 | SSM Run Command | 포트 22를 열지 않아도 되고, SSH 키를 GitHub에 넣지 않아도 된다 |
| 인증 | GitHub OIDC → IAM Role | 장기 액세스 키를 만들지 않는다 |
| 리버스 프록시 | Caddy (컨테이너) | 기존 경험 재사용. ALB는 월 $18라 이 규모엔 과하다 |

### 서버에서 빌드하지 않는 이유

왜샀어 배포 때 1 vCPU 서버에서 `docker build`를 반복하다가 디스크 풀과 SSH 불안정을 겪었다.
빌드를 Actions로 빼면 서버는 `pull` 후 재시작만 하므로 이 문제가 구조적으로 사라진다.

## 구조

```
git push (master)
   │
   ▼
GitHub Actions  ── OIDC ──▶ IAM Role (장기 키 없음)
   │ docker build --platform linux/arm64
   │ push ──▶ ECR
   │
   └─ SSM Run Command ──▶ EC2에서 docker compose pull && up -d

EC2 t4g.small (ap-northeast-2, Ubuntu 24.04 arm64)
   ├─ Caddy  :80 :443   서브도메인별 라우팅 + HTTPS 자동 발급
   ├─ app-a            docker network "web"
   ├─ app-b
   └─ n8n
```

앱은 호스트 포트를 열지 않는다. 전부 `web` 네트워크에 붙고, 외부에서 들어오는 건 Caddy의 80/443뿐이다.

## 비용

| 리소스 | 2026-12-31까지 | 2027-01-01부터 |
|---|---|---|
| EC2 t4g.small | **$0** (무료 트라이얼) | 약 $15 |
| EBS gp3 30GB | 약 $2.7 | 약 $2.7 |
| Elastic IP | $0 (인스턴스에 연결된 상태) | $0 |
| ECR | 약 $0.1 | 약 $0.1 |
| 데이터 전송 | $0 (월 100GB 무료 범위) | $0 |
| **합계 (월)** | **약 $3** | **약 $18** |

신규 계정 가입 크레딧 $100~200이 있으므로 초기 몇 달은 실질 $0이다.

> **2026-12-31에 t4g 무료 트라이얼이 끝난다.** 캘린더에 넣어둘 것.
> 750시간은 전 리전 합산이므로 인스턴스를 2대 띄우면 초과분이 과금된다.
>
> **t4g 트라이얼은 Paid 플랜에서만 받을 수 있을 가능성이 높다.** AWS 문서상 단기 트라이얼은
> Paid 플랜 전용이고, t4g 트라이얼(기간 한정 + 월별 무료 한도)이 그 정의에 들어맞는다.
> 계정 플랜을 먼저 확인하고, 인스턴스 기동 후 Billing → Free Tier에서 실제로 잡히는지 볼 것.

## 과금 사고 방지 — 인스턴스 만들기 전에 할 것

EC2의 유일한 실질 리스크는 모르는 사이 늘어나는 요금이다. 아래 셋이면 사실상 막힌다.

1. **AWS Budgets 예산 + 알람** 설정 — 연말까지는 **$10**(예상 월 $3), 2027-01에 **$30**으로 상향. 실제 85% / 실제 100% / **예측 100%** 세 알림
2. **NAT Gateway를 만들지 않는다** — 월 약 $35. VPC 마법사가 기본으로 권하므로 모르고 켜는 사고가 가장 흔하다. 퍼블릭 서브넷만 쓰면 필요 없다
3. **Elastic IP는 반드시 인스턴스에 연결해 둔다** — 연결돼 있으면 무료, 떼어두면 과금된다

## 미리 알아둘 함정

- **arm64 빌드가 필요하다.** Actions에서 `ubuntu-24.04-arm` 러너를 쓰면 네이티브로 빌드된다. 이 러너는 퍼블릭 저장소에선 무료지만 프라이빗 저장소에선 과금되므로, 프라이빗이면 QEMU 에뮬레이션(느림)을 쓰거나 저장소를 퍼블릭으로 둔다.
- **RAM 2GB에는 스왑이 필수다.** 없으면 빌드 아닌 작업에서도 OOM이 난다. bootstrap에서 2GB 잡는다.
- **왜샀어를 나중에 합칠 때 컨테이너는 1개만 띄워야 한다.** KIS 레이트리밋 큐가 프로세스 전역 변수라 2개 이상이면 1.1초 간격 보장이 깨진다.
- **SSM 연결에는 아웃바운드 443이 필요하다.** 퍼블릭 서브넷 + 인터넷 게이트웨이면 된다. VPC 엔드포인트는 유료라 만들지 않는다.
